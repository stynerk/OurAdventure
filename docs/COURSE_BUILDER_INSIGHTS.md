# 코스 구성 개선안 — 레퍼런스 분석 (여행 미리가봄)

작성일: 2026-10-30 · 담당: PM(Claude) · 근거: 사용자가 공유한 토스 미니앱 "여행 미리가봄" 화면 8장
목적: 우리 F2(여행·코스·스탬프 생성)의 **코스 만들기 경험**을 더 쉽고 빠르게 만든다. 스탬프 투어라는 정체성은 유지한다.

## 1. 레퍼런스 흐름 요약

| 단계 | 화면 | 눈여겨볼 점 |
|---|---|---|
| ① 홈 | "어디로 가볼까?" · 어디로(목적지) + 언제(날짜) 카드 2개 · "이 여행 만들기" · 추천 여행지 9개(사진 카드) | 첫 화면에서 **목적지·날짜 두 가지만** 묻는다. 해외 도시도 같은 방식 |
| ② 방식 선택 | "일정은 어떻게 짤까요?" — **자동으로 짜 주세요**(패키지처럼 날짜별) / **직접 고를게요**(친구와 함께 정함) | 빈 화면 대신 **두 갈래 선택**으로 시작 |
| ③ 자동 옵션 | ① 며칠(당일~5박 6일 칩) ② 어떤 여행(대표 명소·맛집·쇼핑·느긋한 휴양·야경 카드, 복수 선택) | 추천 근거를 밝힌다: "대표 명소는 실제 여행사 패키지 4개 일정에 들어간 곳" + 동선 설명 + "가까운 곳끼리 같은 날, 하루 3~4곳, 도착·돌아가는 날은 2~3곳" |
| ④ 내 프로필 | 캐릭터 선택 · 이름 · 성격유형 · 체력/계획력/실행력/주량 슬라이더 · 약관 동의 | 재미 요소지만 입력이 많다 |
| ⑤ 초대 | 여행 커버 + "같이 갈 친구를 불러 볼까요?" · **자동 작성된 초대 문구**("10월 30일부터 3박 4일, 자매국수·용두암 외 11곳 골라 뒀어") · "혼자 먼저 둘러볼게요" | 코스를 만든 **직후**에 초대. 친구는 "얼굴만 고르면" 입장 |
| ⑥ 일정 | 탭: 가볼 곳 · 일정 · 숙소 · 경비 / DAY 칩(날짜 + 장소 수) / 일차 카드: 지역 제목, 이동 합계(31분·8.8km), "10시 출발 기준", 날짜 메모 / 장소 줄: 번호·시각·사진·이름·분류·머무는 시간 / 장소 사이 이동 수단·시간·거리 | **하루 단위로 읽히는 일정표**. 사진·시간·이동이 한눈에 |

## 2. 우리에게 가져올 인사이트

### 반영 (MVP 범위 안)

1. **목적지 + 날짜 한 화면 시작.** 새 여행 첫 화면을 "어디로 · 언제" 카드 2개 + 주 버튼 1개로 줄인다. 여행명은 "우리의 {목적지} 여행"으로 자동 채우고 나중에 바꾼다.
2. **두 갈래 시작: "자동으로 짜 주세요 / 직접 고를게요".**
   - 자동: 일정 길이 + 여행 스타일을 고르면 추천 장소가 **일차별로** 채워진 초안이 나온다.
   - 직접: 지금처럼 검색해서 담는다.
   - 어느 쪽이든 결과는 같은 편집 화면(초안)이고 리더가 확정한다.
3. **가족용 여행 스타일 칩.** 레퍼런스의 쇼핑·야경 대신 우리 사용자에 맞춘다: **대표 명소 · 체험·놀이 · 자연·산책 · 먹거리 · 느긋하게**(복수 선택). 스타일은 Places 검색 분류로 변환한다(장소는 계속 지도 검색에서만 온다, 하이브리드 원칙 유지).
4. **일차 자동 배분 규칙을 화면에 밝힌다.** "가까운 곳끼리 같은 날 · 하루 3~4곳 · 첫날·마지막 날은 2~3곳". 배분은 AI가 아니라 **좌표 기반 묶기 + 규칙**으로 한다(예측 가능, 비용 없음).
5. **코스 탭을 일정표로.** DAY 칩(날짜 + 장소 수) → 일차 카드(지역 이름, 이동 합계, 날짜 메모) → 장소 줄(순서·예상 시각·사진·이름·머무는 시간·**도장 상태**) → 장소 사이 이동 시간·거리. 우리만의 차별점은 각 줄의 **도장 미니**와 미션 1줄이다.
6. **코스 직후 초대 + 자동 초대 문구.** 여행 확정 직후 초대 시트를 띄우고, 문구를 자동으로 만든다: "{목적지} 같이 가자! {시작일}부터 {N박 M일}, {장소1}·{장소2} 외 {K}곳 도장 모으러 가요". "나중에 초대할게요"도 둔다.

### 후속 (MVP 이후)

7. **가볼 곳 후보 + 함께 고르기(PICK).** 멤버가 후보를 담고 👍 하면, 리더가 표를 보고 확정한다. "직접 고를게요" 모드의 확장.
8. **실제 이동 시간.** MVP는 직선거리 기반 **추정**("약 20분")으로 표시하고, 정확한 경로 시간(Google Routes API)은 비용 확인 후 도입한다.
9. **숙소·경비 탭.** 스탬프 투어의 핵심이 아니므로 보류.

### 가져오지 않음

- **성별·성격유형·체력·주량 같은 프로필 입력**: 참여 시간을 늘리고(목표 45초), 사람을 특정하는 정보가 되며, 아이가 함께 쓰는 서비스와 맞지 않는다. 우리는 **별칭 + 아바타 색**만 유지한다. 여행 전체에 "많이 걷기 / 조금 걷기" 한 가지만 두는 것은 검토한다(일차 배분 개수 조정용).
- 이모지 아이콘: 디자인 가이드(Lucide 선 아이콘)를 따른다.

## 3. 바뀌는 흐름 (리더)

```
그룹 홈 → [새 여행]
 → ① 어디로·언제 (목적지 검색 + 날짜)
 → ② 어떻게 짤까요? ── 자동 → ③ 일정 길이(날짜에서 자동) · 스타일 칩 · 걷기 정도
 │                    └ 직접 → 검색해서 담기
 → ④ 코스 초안 (DAY별 장소 · 순서 변경 · 빼기/추가 · AI 미션 생성 버튼)
 → [여행 만들기] → ⑤ 초대 시트 (자동 문구 · 링크 공유 / 나중에)
 → 여행 지도 탭
```

목표 지표 유지: 리더가 여행·코스를 만들고 링크 공유까지 **3분 이내**. 자동 모드는 **1분 이내**를 새 목표로 측정한다.

## 4. 데이터·분석 영향

- 장소(Place)에 `day`(1부터), `order`(일차 안 순서), `plannedTime`(선택, "10:00"), `stayMinutes`(선택), `category`(Places 분류 요약)를 추가한다. 기존 `order`만 있는 여행은 `day = 1`로 본다.
- 여행(Trip)에 `buildMode`(`auto`·`manual`), `styles`(배열), `pace`(`light`·`normal`), 일차별 `dayNotes`를 추가한다.
- 분석 이벤트(ANALYTICS_SPEC에 추가 예정): `course_mode_select`(mode), `course_auto_generate`(styles_count, days, place_count, result: success·empty·error), `course_day_edit`(action: move·remove·add), `invite_sheet_view`, `invite_share`(source: after_create·trip_menu). 장소 이름·좌표는 보내지 않는다.
