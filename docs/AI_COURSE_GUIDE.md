# AI 코스 구성 가이드 (하이브리드) — 기획 초안

작성일: 2026-10-26 · 담당: 기획(Claude) · 상태: 사용자 검토용. [PRD v2](PRD_V2.md) F2의 상세 기준이다.

근거: Codex의 [경주 AI 핸드오버](engineering/GYEONGJU_AI_HANDOFF.md)와 [경주 코스 참조 JSON](../development/reference/gyeongju-course.json).
경주 콘텐츠는 2026-10 가족여행용 계획이며 실제 방문 기록이나 현재 운영 정보가 아니다.

## 1. 경주 사례에서 가져올 것

아이가 좋아했던 경주 앱의 스탬프 하나는 네 가지로 이루어져 있었다. AI는 이 형식을 그대로 만든다.

| 요소 | 경주 예시 (대릉원) | 역할 |
|---|---|---|
| 스탬프 이름 | 왕의 언덕 | 장소명보다 재미있는 별명. 스탬프판에 표시 |
| 질문형 제목 | 왕의 언덕에는 누가 잠들어 있을까? | 호기심을 여는 한 문장 |
| 관찰 미션 | 봉분의 높이, 폭, 붙어 있는 모양을 비교해 봐 | 현장에서 3~5분 안에 하는 행동 |
| 사진 아이디어 | 마음에 든 봉분을 배경으로 손으로 왕관 모양 만들기 | 스탬프 완료 사진을 찍는 방법 |

함께 지킬 원칙:

- 짧은 문장, 초등 저학년이 읽을 수 있는 말.
- 순서를 바꾸거나 건너뛰어도 불이익이 없다.
- 식사·휴식·이동은 일정에는 들어가도 스탬프로 만들지 않는다.
- 인접한 장소를 같은 날로 묶는다.

## 2. 역할 나누기

| 단계 | 담당 | 만드는 것 |
|---|---|---|
| 장소 찾기 | **지도 검색** | 실제 장소 이름·위치·주소 |
| 날짜 배치 | 앱 규칙(+AI 제안) | 위치가 가까운 장소끼리 일차 묶기 |
| 스탬프 내용 | **AI** | 스탬프 이름·질문형 제목·관찰 미션·사진 아이디어 |
| 확정 | **리더** | 장소 추가·삭제·순서, 문구 수정 |

AI는 장소를 새로 만들지 않는다. 지도 검색이 준 장소 목록 안에서만 쓴다.

## 3. 입력 (MVP)

| 입력 | 필수 | 비고 |
|---|---|---|
| 목적지 | 필수 | 지도 검색어 |
| 여행 기간 | 필수 | 일차 수 계산 |
| 아이 나이 | 선택 | 없으면 "초등 저학년" 기준 |
| 첫날 도착 시간 | 선택 | 늦으면 첫날 장소 수를 줄임 |
| 꼭 갈 곳 / 뺄 곳 | 선택 | 리더가 목록에서 직접 고쳐도 됨 |

이동 수단·관심사·예약 정보 입력은 후속이다. 입력이 없을 때 AI가 예약·숙소·가족 구성을 지어내지 않는다.

## 4. 출력 형식 (AI → 앱)

```json
{
  "days": [
    {
      "day": 1,
      "places": [
        {
          "placeId": "<지도 검색 결과 id>",
          "stampName": "왕의 언덕",
          "question": "왕의 언덕에는 누가 잠들어 있을까?",
          "observation": "언덕들의 높이와 모양을 비교해 봐. 멀리서 한 번, 가까이서 한 번!",
          "photoIdea": "마음에 든 언덕을 배경으로 손으로 왕관 만들기"
        }
      ]
    }
  ]
}
```

- `placeId`는 입력으로 받은 지도 검색 결과의 id만 쓸 수 있다. 앱은 목록에 없는 id를 버린다.
- 하루 3~4곳, 여행 전체 최대 10곳.
- 글자 수: 스탬프 이름 10자, 질문 30자, 관찰 미션 50자, 사진 아이디어 40자 안팎.

## 5. 문장 규칙과 금지사항

**쓴다**

- 보고·찾고·비교하고·따라 하는 **관찰형** 행동 (색깔 찾기, 크기 비교, 포즈 따라 하기, 소리 듣기).
- 장소의 겉모습만으로 할 수 있는 미션.
- 반말 톤의 친근한 말투 ("~해 봐", "~찾아볼까?").

**쓰지 않는다**

- 운영 시간·가격·휴관·예약 가능 여부 등 확인되지 않은 사실.
- 정확한 연도·인물·수치 같은 역사 사실의 단정. 꼭 필요하면 질문형으로만.
- 만지기·올라가기·출입 제한 구역 진입·위험한 포즈.
- 촬영이 금지될 수 있는 실내 전시물 근접 촬영 강요. 실내 장소는 "건물 밖" 사진 아이디어를 함께 준다.
- 다른 아이와의 경쟁, 순위.

## 6. 실패·확인 처리

- AI 실패·지연: 장소 목록은 그대로 두고, 기본 문구(장소명 + "사진을 찍어 스탬프를 모아요")로 여행을 만들 수 있다.
- 리더가 확정하기 전까지 멤버에게 보이지 않는다.
- 목적지를 바꾸면 이전 목적지의 장소·문구를 모두 지운다.
- 앱은 "운영 정보는 방문 전에 확인하세요" 안내를 코스 화면에 둔다.

## 7. 프롬프트 구성 (Engineering 구현 기준)

1. 시스템 지시: 위 5장의 규칙, 4장의 출력 형식.
2. 예시: 경주 참조 JSON의 9개 장소 중 3~4개를 형식 예시로 넣는다(`stampName`, `contentTitle`, `observationReference`, `photoIdea` → 4장 필드로 매핑).
3. 입력: 지도 검색 결과(id·이름·분류·좌표), 기간, 선택 입력.
4. 검증: 응답 JSON 형식·글자 수·placeId를 서버에서 확인하고, 어긋나면 한 번만 다시 요청한 뒤 기본 문구로 대체한다.

모델·지도 API·호출 비용은 Engineering이 견적을 낸 뒤 사용자가 정한다.

## 8. 결정이 필요한 것

| 항목 | 기획 권장 |
|---|---|
| 빠른 생성(목적지만) vs 상세 생성 | MVP는 목적지 + 기간. 나이·도착 시간은 선택 입력 |
| 식사·휴식·이동 포함 | MVP는 스탬프 장소만. 일정표는 후속 |
| 스탬프 이름·사진 아이디어까지 AI가 만들지 | 만든다 (경주 앱의 재미 요소) |
| 운영 정보 확인 시점 | 지도 API가 주는 정보만 표시, 나머지는 "방문 전 확인" 안내 |
