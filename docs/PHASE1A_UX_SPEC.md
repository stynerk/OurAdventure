# Phase 1A UX & Content — 개발용 화면 명세

최신 통합 검토: [Phase 1 PRD](PHASE1_PRD.md) · [화면 매핑·검증 기록](PHASE1_WIREFRAMES.md) · [클릭형 와이어프레임](wireframes/index.html). 아래는 기존 상세 UX 초안이며 정책 수치의 승인 근거가 아니다.

작성: 2026-10-20 · 담당: UX & Content · 상태: 개발 명세 초안, 제품/기술 정책 확정 및 실행 QA 전

## 1. 적용 기준과 범위

- 상위 기준은 `PHASE1_SHARED_ADVENTURE_SPEC.md` v1.1 **0절**이다. 충돌 시 0절을 따른다.
- 승인 범위: 가족·지인 여행, 리더 포함 최대 10명(리더 1명+일반 구성원 최대 9명), 활동 공간당 여행·활동 1건.
- 핵심 흐름: 생성 → 링크 초대 → 공동 글·사진·활동 기록 → 구성원 함께 보기 → 리더 기록 선택·순서 조정 → 일기/앨범 출력.
- 기존 경주 9개 Quest와 공동 스탬프를 재사용한다. 개인 모드 선택, 학교 코드·개인 제출·성적·학교 보고서는 노출하지 않는다(1C).
- 30명은 1B 검증 목표이며 출시 한도로 안내하지 않는다. 계정별 생성 가능 공간 수는 미결정이다.
- 본 문서의 화면 구성·문구·AC는 구현 제안이다. 하단의 미결정 권한·저장 정책을 사용자 승인으로 승격하지 않는다.

## 2. 기존 경험 보존과 탐색 구조

기존 `/` 앱·사진·자산·`gj-family-quest`, `gj-family-diary-template`는 수정·삭제·자동 업로드하지 않는다. 신규 앱은 `/next/` 등 별도 경로·별도 저장 namespace를 사용한다. 신규 출력 초안도 기존 저장 키에 기록하지 않는다.

기존 종이색 배경, 짙은 녹색 CTA, 따뜻한 일러스트, 둥근 카드, 짧고 친근한 한국어를 재사용한다. 모바일 4탭 **지도 / 코스 / 스탬프 / 추억**을 유지한다. 신규 공간의 기본 도착지는 **추억(공동 게시판)**으로 하여 공유 기록을 먼저 보여준다. 지도는 GPS·길찾기가 아니라 Quest 진입 화면이다.

| 화면 | 경로 제안 | 접근 | 주요 구성 |
|---|---|---|---|
| 시작 | `/next/` | 누구나 | 탐험방 만들기, 초대 링크 이용 안내, 내 여행 |
| 내 여행 | `/next/mine` | 인증 상태에 따라 | 리더 소유 공간 목록, 동일 세션 참여 공간 진입 |
| 생성 | `/next/create` | Google 로그인 리더 | 이름, 경주 고정 코스, 생성 |
| 초대 입장 | `/next/join/:token` | 초대 링크 방문 | 여행 소개, 별칭, 함께 보기 안내, 참여 |
| 추억 게시판 | `/next/r/:roomId/board` | 공간 구성원 | 기록 목록, 기록 남기기, 리더 출력 |
| 기록 작성/수정 | `/next/r/:roomId/posts/new`, `posts/:postId/edit` | 서버가 허용한 구성원 | 글·사진·장소/Quest 연결 |
| 기록 상세 | `/next/r/:roomId/posts/:postId` | 공간 구성원 | 본문·사진·작성자·연결 활동·허용 작업 |
| 관리 | `/next/r/:roomId/manage` | 리더 | 인원, 초대 링크, 구성원, 여행 종료 |
| 출력 | `/next/r/:roomId/export` | 리더 | 선택·정렬·템플릿·소감·미리보기·출력 |

경로는 라우터 계약 확정 시 바꿀 수 있다. 초대 token과 내부 roomId 경로를 구별하고, URL만으로 게시판/사진을 열람시키지 않는다. 뒤로 가기는 이전 목록과 스크롤 위치로 복귀한다.

### 공통 모바일·접근성

- 기본 본문 16px 이상, 주요 터치 영역 44×44px 이상. 기존 자산을 쓰되 작은 안내 글자의 가독성을 개선한다.
- 목록·스탬프·카드는 실제 `button`/`a` 사용. 아이콘만 있는 작업에 접근 가능한 이름을 제공한다.
- 하단 내비·작성 CTA가 입력·파일 선택·본문을 가리지 않도록 safe-area와 키보드 노출을 처리한다.
- 모달은 제목·`aria-modal`, 초점 이동/복귀, 키보드 닫기·배경 닫기를 지원한다. 파괴 작업은 배경 터치만으로 실행하지 않는다.
- 저장·업로드·로딩·오류는 텍스트와 상태 영역으로 전달한다. 색·스피너만으로 구분하지 않는다.
- 같은 별칭을 금지한다고 가정하지 않는다. 작성자 표시는 멤버십과 연결하고 본인 항목에 ‘나’를 붙인다. 별칭을 권한 판정에 사용하지 않는다.

## 3. 생성 및 초대 입장

### U01. 시작·내 여행

시작 화면은 기존 일러스트와 ‘함께 남기는 우리 여행’ 설명을 사용한다. ‘탐험방 만들기’는 Google 로그인으로 연결한다. 로그인 취소 시 입력과 현재 화면을 유지한다. 초대 참여자를 로그인 화면으로 강제 이동시키지 않는다.

내 여행은 실제 접근 가능한 공간만 표시한다. 공간 이름·열림/종료·구성원 수를 보여주고, 빈 상태에는 ‘첫 여행을 만들어보자’를 제공한다. 리더가 다른 방에 구성원으로 입장할 때 기존 Google 세션을 익명 계정으로 교체하지 않는다. 익명 참여의 다른 기기 복구 기능은 약속하지 않는다.

### U02. 탐험방 만들기

| 필드/영역 | 동작 |
|---|---|
| 여행 이름 | 추천 이름과 직접 입력 재사용. 기존 2~14자는 UX 제안이며 신규 검증값은 `ROOM_NAME_MIN/MAX` 계약으로 확정 |
| 코스 | ‘경주 역사 탐험 · 주요 미션 9개’ 고정 카드. 코스 제작/개인 모드 선택 없음 |
| 인원 | ‘나를 포함해 최대 10명이 함께할 수 있어’ |
| 생성 | ‘탐험방 만들기’. 처리 중 비활성화·진행 문구, 중복 요청 멱등 처리 |

생성 성공은 서버가 공간과 리더 멤버십을 확정한 뒤 표시한다. 성공 화면은 여행 이름, ‘1 / 10명’, ‘초대 링크 복사’, ‘추억 보러 가기’를 제공한다. 개인의 실명·이메일을 초대 카드에 표시하지 않는다.

### U03. 초대 링크 입장

1. token 확인 중에는 여행명·기록을 추측해서 표시하지 않는다.
2. 유효한 링크에는 공개 가능한 여행 이름·코스·참여 가능 여부만 표시한다. 가입 전 게시글·사진·구성원 명단은 숨긴다.
3. 별칭 입력 및 안내: ‘이 여행의 구성원과 글·사진을 함께 봐. 사진을 올리기 전에 함께 나온 사람에게 확인해줘.’
4. ‘함께하기’ → 인증/기존 세션 확인 → 서버 가입 → 게시판. 익명 인증은 사용자에게 로그인 작업을 요구하지 않는다.
5. 이미 가입한 동일 멤버십은 새 인원을 만들지 않고 복귀한다. 저장 지연·더블 탭도 중복 가입시키지 않는다.

| 입장 실패 | 표시와 다음 동작 |
|---|---|
| 정원 도달 | ‘이 여행은 10명이 모두 함께하고 있어. 리더에게 확인해줘.’ 재시도/돌아가기 |
| 동시 마지막 자리 경쟁 | 서버 결과로 성공 1명만 반영, 실패자는 정원 도달 안내 |
| 잘못된/사용 불가 링크 | ‘참여 링크를 확인할 수 없어. 리더에게 링크를 다시 받아줘.’ |
| 종료된 여행 | 신규 가입하지 않음. 기존 구성원은 허용 정책에 따른 읽기 화면 |
| 인증/네트워크 실패 | 별칭 유지, 재시도. 성공으로 표시하지 않음 |

관리 화면은 리더 포함 인원과 구성원 목록을 제공한다. 링크 복사 실패 시 선택 가능한 링크 텍스트를 보여준다. QR·추방·리더 교체·초대 재발급 UI는 정책/범위 확정 없이 추가하지 않는다.

## 4. 공동 게시판 및 활동 연결

### U04. 추억 게시판

- 상단: 여행 이름, 인원, 열림/종료 상태. 리더는 ‘관리’와 ‘일기·앨범 만들기’에 접근한다.
- 목록: 작성자 별칭, 서버 작성 시각, 본문, 사진 썸네일, 연결된 장소/Quest. 신규 기록은 최신순을 UX 기본값으로 제안한다. 페이지 크기·실시간 구독 범위는 Engineering 계약을 따른다.
- ‘기록 남기기’는 글/사진 작성으로 이동한다. 최초 빈 상태는 ‘첫 사진이나 한 줄로 여행을 시작해보자’와 CTA를 제공한다.
- 목록 새로 반영 시 읽던 위치를 강제로 이동시키지 않는다. 필요 시 ‘새 기록이 있어’ 버튼으로 이동시킨다.
- 사진 없는 글은 빈 이미지 상자를 만들지 않는다. 실패한 사진은 ‘사진을 불러오지 못했어 · 다시 보기’와 본문을 유지한다.
- 첨부 사진은 구성원 인증이 필요한 경로로 조회한다. 유효 토큰/로그인만 있고 멤버십이 없으면 열람할 수 없다.
- Quest 활동은 글·사진과 시각적으로 구별되는 ‘활동 기록’ 카드다. 어떤 이벤트를 게시판에 자동 노출할지는 `ACTIVITY_FEED_TYPES` 결정 전 임의로 확대하지 않는다.

### U05. Quest/스탬프 재사용

지도·코스·스탬프의 9개 Quest 상세 구성(이야기/미션/관찰/지식/사진 아이디어/출처)을 유지한다. 공동 완료 요청은 서버 확정 후 ‘스탬프를 모았어’로 표시한다. 동시에 완료해도 스탬프는 하나다. 글·사진 게시와 Quest 완료는 독립 작업이며, 사진이 없거나 업로드에 실패해도 **사진 없이 완료**할 수 있다.

기록 작성에서 Quest 연결은 선택 사항이다. 자유 기록을 허용하되 코스 편집 기능을 의미하지 않는다. Quest 화면의 ‘기록 남기기’는 해당 Quest만 미리 선택한다. 활동 카드가 동일 게시글을 중복 생성하지 않도록 사건/게시글의 연결 ID를 사용한다.

## 5. 기록 작성·수정·삭제

### U06. 작성

| 영역 | 동작 |
|---|---|
| 본문 | ‘오늘의 순간을 한 줄로 남겨줘’. 길이/남은 글자 수는 `POST_TEXT_MAX` 사용 |
| 사진 | ‘사진 촬영’(`capture=environment`)과 ‘갤러리/파일 선택’을 분리. 장수/크기/형식은 설정값으로 안내 |
| 사진 미리보기 | 선택 후 순서·제거, 처리 상태·실패 원인 표시. 썸네일 alt는 기록/장소 맥락 사용 |
| 활동 연결 | ‘장소 연결 안 함’ 또는 기존 9개 Quest 선택 |
| 공개 범위 | ‘이 여행의 구성원에게 보여’ 고정 안내. 외부 공개 토글 없음 |
| 게시 | 글 또는 사진 중 하나 이상. 빈 공백만 있으면 사진 없는 게시 불가 |

사진 설정은 기존 로컬 720px/.65를 신규 공유 정책으로 자동 채택하지 않는다. 선택 취소는 기존 입력을 보존한다. 지원 형식·용량 위반은 업로드 전에 표시한다. 실제 압축/업로드 중에는 단계별 문구와 다시 시도를 제공한다.

게시 완료는 첨부 저장과 서버 게시글 확정 후에만 표시한다. 부분 실패 시 성공한 글처럼 목록에 노출하지 않으며, 재시도 시 게시글/사진을 중복 생성하지 않는다. 글·선택한 사진은 현재 화면에서 유지한다. 정리되지 않은 임시 업로드의 처리 방식은 Engineering 계약이 필요하다.

뒤로 가기/닫기에서 미저장 변경이 있으면 ‘작성하던 내용을 나갈까?’와 ‘계속 쓰기/나가기’를 제공한다. 오프라인 자동 전송/오프라인 큐는 없다. 임시 입력이 새로고침 후 복구된다고 약속하지 않는다. 세션이 끊기면 재인증 안내와 복사 가능한 본문을 제공하되 타 사용자 세션에 초안을 노출하지 않는다.

### U07. 상세·수정·삭제

원문 PRD에 게시글 수정/삭제의 최종 권한 계약이 없으므로 아래는 **Product/Engineering 확정이 필요한 UX 제안**이다. 권한 확인 전 실제 활성 UI를 출시하지 않는다.

| 대상 | 열림 상태 제안 | 종료 후 |
|---|---|---|
| 작성자 본인 | 본인 글/사진 수정·삭제 | `POST_EDIT_AFTER_CLOSE` 정책 필요 |
| 다른 구성원 | 읽기만, 수정·삭제 숨김 | 읽기 정책 적용 |
| 리더의 다른 사람 기록 | 출력 선택·정렬만. 원문 수정 권한을 추정하지 않음 | 출력/보관 정책 필요 |
| 리더 삭제/관리 삭제 | `LEADER_POST_DELETE` 확정 후 조건부 노출 | 동일 정책 필요 |

수정은 기존 본문·사진을 로드한다. 사진 교체 실패 시 이전 저장본을 유지한다. 수정 중 다른 세션이 변경하면 충돌을 알리고 새 내용 확인/다시 작성 동작을 제공한다. 묵시적으로 덮어쓰지 않는다.

삭제는 ‘이 기록을 삭제할까? 구성원 게시판에서도 보이지 않게 돼.’ 확인 후 서버 확정 시 목록에서 제거한다. 네트워크 실패 시 원문을 유지하고 재시도를 제공한다. 실제 원본/출력 사본/백업 삭제 범위와 보관 기간은 정책 확정 전 ‘완전히 영구 삭제’라고 안내하지 않는다. 이미 내려받은 출력물은 회수할 수 없음을 삭제 안내에 포함한다.

## 6. 리더 기록 선택·정렬·출력

### U08. 선택 → 정렬 → 꾸미기 → 미리보기

1. 리더만 진입. 다른 구성원의 직접 URL 접근은 서버에서도 거부한다.
2. 접근 가능한 공동 기록을 사진·작성자·문구와 함께 선택한다. 전체 선택/해제와 선택 개수를 제공한다. 0개면 다음 비활성화.
3. 선택한 기록만 출력 순서대로 나열한다. ‘위로/아래로’ 버튼을 기본 제공하고, 드래그는 선택 보조 수단으로만 둔다. 정렬은 원본 게시판 순서나 타인의 기록을 변경하지 않는다.
4. 기존 A 사진 앨범/B 스크랩북/C 그림일기 배경을 재사용한다. 기본 C를 유지한다. 학교 보고서·AI 요약·자유 편집기는 제공하지 않는다.
5. 기존 대표사진(album), 소감 3개 각 50자, 별점(journal)을 재사용한다. 새로운 여행명·날짜를 사용하고 2026.10.9~11 제목을 하드코딩하지 않는다. 활동 날짜 수집/표시 계약은 Product 확정 필요.
6. 선택/정렬 결과로 A4 미리보기를 생성한다. 글과 사진, 작성자 표기가 출력에서 누락·혼합되지 않는지 확인한다. 긴 게시글의 출력 문구는 `EXPORT_TEXT_MAX`에 따라 길이 안내/별도 출력 캡션으로 처리하며 원문을 수정하지 않는다. 조용히 잘라내지 않는다.
7. ‘이미지 저장’과 ‘A4 인쇄’를 제공한다. 기존 2480×3508 PNG, 세로·페이지 맞춤·머리글/바닥글 끄기 안내와 인쇄 후 화면 복귀를 유지한다.

기존 출력기는 Quest 기록 9개를 전제로 한다. 신규 공유 게시글을 임의 개수 넣어 한 장에 맞춘다고 보장하지 않는다. `EXPORT_MAX_RECORDS/PHOTOS`를 레이아웃 검증 후 결정하고 초과 선택을 설명한다. 여러 페이지 자동 앨범은 승인 범위로 가정하지 않는다. 게시글당 여러 사진을 허용할 경우 출력할 사진 선택 규칙도 확정해야 한다.

### 출력 실패/변경 처리

- 선택 기록이 삭제·권한 변경되면 제거 사실을 알리고 재확인한다. 로드된 숨은 캐시만으로 계속 출력하지 않는다.
- 사진 일부 로딩 실패 시 위치를 명시하고 재시도 또는 해당 항목 제외를 사용자가 선택한다. 사진이 빠진 결과물을 성공처럼 자동 다운로드하지 않는다.
- 생성 중 버튼 중복 실행 차단, ‘A4 추억을 만드는 중…’, 실패 후 선택·순서·소감 보존.
- canvas 출력은 공유 사진 CORS/인증 방식까지 검증한다. 외부 사진 URL을 넣고 실제 PNG 생성이 안 되는 상태는 완료가 아니다.
- 인쇄 창 실패/저장 동작 차이는 ‘이미지를 저장한 뒤 인쇄해줘’ 안내. 저사양 기기 메모리 오류 시 재시도/선택 수 줄이기 제공.

## 7. 종료 및 공통 오류 상태

| 상황 | 화면 계약 |
|---|---|
| 리더 여행 종료 | 재오픈 미지원과 진행 변경 중단을 확인시킨 뒤 서버 종료. 게시글 편집·출력 종료 후 정책은 별도 확정 |
| 종료와 작성 동시 발생 | 게시 요청의 서버 결과를 반영. 실패 시 본문 유지, 성공으로 알리지 않음 |
| 접근 거부 | ‘이 여행을 볼 권한을 확인할 수 없어.’ 안전한 시작/내 여행 이동, 다른 여행 데이터 미노출 |
| 통신 끊김 | ‘연결이 끊겼어. 다시 연결한 뒤 저장해줘.’ 저장 완료/자동 전송 약속 없음 |
| 오래된 목록/재연결 | 마지막 갱신 상태 표시, 재조회. stale 상태로 권한/정원을 확정하지 않음 |
| 사진 한도/공간 비용 제한 | 실제 설정에서 제공한 남은 한도·중단 사유·다음 행동. 미결정 숫자를 하드코딩하지 않음 |
| 보관 종료/삭제된 여행 | 이용 가능 여부·보관 정책에 맞는 안내. 남은 로컬 이미지로 비공개 콘텐츠 노출하지 않음 |

## 8. 구현 전 확정할 계약

| 계약 | UX에 필요한 값/판정 | 담당 |

| 접근/삭제 | 구성원 사진 접근 방식, `LEADER_POST_DELETE`, 본인 수정·삭제, 권한 변경·임시 파일 정리 | Product+Engineering |

| 보관 | `RETENTION_POLICY`, 사용자 삭제/백업/내려받은 사본 안내 | Product+Engineering |
| 초대 | 만료/재발급/종료 후 가입, 안전한 미가입자 소개 정보 | Product+Engineering |
| 출력 | `EXPORT_MAX_RECORDS/PHOTOS`, `EXPORT_TEXT_MAX`, 다중 사진 선택·글 전용 배치·날짜 | UX+Product+Engineering |

## 9. Acceptance Criteria 및 인계

| ID | 재현 가능한 AC |
|---|---|
| AC01 | 기존 두 저장 키·사진·퇴역 기록을 준비하고 신규 앱에서 생성/입장/출력한 뒤 루트로 복귀해도 기존 데이터가 동일하다. |
| AC02 | 리더 Google 로그인 취소/재시도, Google 사용자 타 방 참여에서 기존 인증 세션이 의도치 않게 익명으로 바뀌지 않는다. |
| AC03 | 중복 생성/가입 요청은 같은 결과로 수렴한다. 리더 포함 10명 도달 후 신규 가입과 동시 마지막 자리 경쟁을 서버에서 제한한다. |
| AC04 | 링크만 가진 미가입자/다른 여행 구성원은 게시글·원본 사진·출력 데이터를 직접 URL/API로 읽을 수 없다. |
| AC05 | 글만/사진만/글+사진 게시가 가능하고, 공백만/설정 초과/지원 불가 파일은 실패 사유를 보인다. 업로드 실패·취소·재시도로 이전 입력과 저장본이 소실·중복되지 않는다. |
| AC06 | 구성원 2개 독립 세션에서 서버 확정한 글·사진을 함께 본다. 정상 네트워크 반영 목표 5초는 검증 목표이며 결과를 기록한다. |
| AC07 | 승인된 수정·삭제 권한만 노출하고 서버에서도 강제한다. 실패·동시 수정·삭제 충돌에서 기존 내용 보존/재확인 동작이 있다. |
| AC08 | 사진 없이 공동 Quest 완료 가능. 동시 완료는 스탬프 하나이며 게시글 작성 실패를 완료 성공과 혼동하지 않는다. |
| AC09 | 리더가 기록을 선택·버튼으로 재정렬하고 A/B/C 미리보기·PNG·A4 출력에서 같은 순서를 확인한다. 작성자 원문과 게시판 순서는 변하지 않는다. |
| AC10 | 출력 한도·긴 글·사진 0/1/한도·사진 실패·권한 변경·인쇄 취소에서 잘림/누락을 숨기지 않고 선택 결과를 보존한다. |
| AC11 | 종료 후 가입/쓰기/출력은 확정 정책과 서버 판정에 일치한다. 오래 열린 작성 화면도 우회할 수 없다. |
| AC12 | iOS Safari/Android Chrome에서 4탭·촬영/파일 입력·키보드·스크롤·44px 터치·접근 가능한 이름·모달 초점·A4 실인쇄를 검증한다. |
| AC13 | 1A 화면에 개인 모드 선택·학교 제출/코드·학교 보고서·30명 지원 보장·기존 사진 자동 이전이 없다. |

Handoff To: Product는 8절 정책 확정, Engineering은 화면/데이터/서버 권한·공유 업로드·출력 연동, QA는 AC01~13 실행 증거 기록. 이 문서는 화면명세 작성 완료이며 구현·Firebase 연결·실기기 QA·출시 완료를 의미하지 않는다.
