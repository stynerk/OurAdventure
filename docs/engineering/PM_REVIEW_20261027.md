## 공개 운영 상태

고정 공개 URL을 HTTP GET으로 확인했으며 자격증명·설정값을 읽어 출력하거나, 사용자 데이터에 접근하거나, 운영 로그인/분석 이벤트를 만들지 않았다.

| 주소 | 결과 |
|---|---|
| `https://stynerk.github.io/OurAdventure/` | 200, 기존 경주 앱 |
| `https://stynerk.github.io/OurAdventure/next/` | 404 |
| `https://stynerk.github.io/OurAdventure/next/firebase-config.js` | 404 |

따라서 이 공개 주소에서는 새 그룹·여행 서비스가 아직 배포되지 않았다. localhost에서 GA가 수신됐다는 PM 확인과 운영 연결을 구분한다. 공개 `/next`가 없으므로 해당 화면의 운영 Google 로그인·Functions·GA 수신이 정상이라고 판단할 수 없다. 다른 운영 도메인/배포가 있다면 그 주소의 별도 확인이 필요하다.

운영 연결은 승인된 PR 순서의 통합, 공개 웹 설정·함수·Rules의 배포, OAuth 허용 도메인 확인 후 실제 환경에서 검증해야 한다. Blaze/Places/Storage/AI의 미결정 항목과 GA 관리 설정은 PM 상태 문서의 대기 상태를 유지한다.

## 이후 작업에서 점검을 반영하는 절차

개발 시작 시 PM 점검 PR과 대상 티켓 PR의 본문·최신 diff·리뷰·댓글을 읽는다. 구현 가능한 의견은 해당 티켓에 반영하고, 결정·권한·비용이 필요한 항목은 근거와 남은 조건을 engineering 보고서 및 PR에 명시한다. PR을 정리하기 전에 최신 PM 갱신을 다시 확인한다. 실제 수행한 확인과 PM이 보고한 확인을 구분한다.
