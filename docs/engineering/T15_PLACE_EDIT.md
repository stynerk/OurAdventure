# T15 장소 추가·삭제

PR #21 `5f0b9a8` 위 `engineering/place-edit`. 디자인 가이드 v2의 색·글꼴·둥근 버튼·시트를 사용한다.

진행 중 여행의 리더에게만 코스 탭의 `+ 장소 추가`와 각 장소의 삭제 버튼을 제공한다. 장소 이름은 100자, 여행당 활성 장소는 기존 한도인 10개다. 추가 요청 ID와 입력은 UID·그룹·여행별 로컬 저장 공간에 먼저 보관한다. 응답 유실·새로고침 뒤에도 같은 요청을 확인하므로 새 장소를 중복 생성하지 않는다. 저장 공간 오류가 나면 서버 호출을 시작하지 않는다. 기존 addTripPlace의 서버 권한·트랜잭션·완료 보존을 사용한다.

열린 여행은 Firestore의 서버 확인 `placeIds` 변경을 구독한다. 추가·삭제 시 리더와 멤버 모두 화면을 다시 읽으며, 기존 완료는 활성 장소 ID별로 유지한다. 자신의 추가·삭제 요청 중에는 해당 화면의 자동 재진입을 미뤄 입력과 재시도 상태를 유지한다. 경로·계정 변경 시 구독과 대화상자를 정리한다.

## 삭제 범위와 확인

삭제는 **장소를 코스·도장판에서 제외**하는 동작이다. 다른 사람이 쓴 사진·한 줄·원본 게시글은 변경하거나 삭제하지 않는다. 추억에서는 `삭제된 장소`로 표시한다. 게시글별 수정·삭제는 작성자에게만 허용하며 리더도 타인 원본을 바꿀 수 없다. 장소 문서는 삭제 표식을 남겨 작성자의 기존 사진 삭제와 카운터 정리가 계속 동작하게 한다. 과거 완료도 저장 상태는 보존하지만 활성 장소 집계·리포트 도장 수에서는 제외한다. 사진 총수·한 줄 모음에는 보존한 기록이 포함된다.

`previewTripPlaceRemoval`은 리더·진행 상태를 검사하고 확정 사진 수 및 서로 다른 작성자 수를 계산한다. 미확정·삭제된 게시글은 포함하지 않는다. 사진이 있으면 UI가 영향·보존 정책과 취소/삭제 버튼을 보여준다. 사진이 없으면 확인 대화상자 없이 삭제한다.

`removeTripPlace`는 같은 권한을 다시 검사한다. 사진이 남았으면 현재 확정 사진 집합에 맞는 확인 토큰을 요구한다. 확인 사이 사진이 추가·삭제되면 이전 확인을 거부하고 최신 영향을 다시 보여줘 새 확인을 받는다. 사진 수와 장소 순서는 트랜잭션에서 읽고, 장소 표식·여행의 placeIds/placeCount를 함께 갱신한다. 중복 삭제는 횟수를 다시 차감하지 않는다. 삭제와 사진 확정이 경쟁하면 하나가 먼저 확정되고, 후속 요청은 변경된 상태를 검증한다. 제거된 장소의 새 사진 확정은 거부한다.

종료 여행은 추가·삭제 버튼이 없으며 두 삭제 callable과 새 추가 요청도 서버에서 거부한다. Firestore/Storage 보안 규칙이나 역할 권한은 변경하지 않는다.

## 입력 방어와 지도

그룹·여행·참여·기존 공동방의 비활성 폼 제출은 FormData를 만들기 전에 무시한다. 추가 폼도 처리 중 합성 submit을 무시한다. 기존 사진 재시도의 비활성 fieldset은 별도 동작이므로 변경하지 않는다.

지도 해는 배경 SVG의 비균등 확대에서 분리한 정사각형 SVG 안에 그린다. 완료 핀은 같은 장소 순번의 도장 면/글자 색을 사용한다. 종료 미완료 핀은 기존 회색을 유지한다.
