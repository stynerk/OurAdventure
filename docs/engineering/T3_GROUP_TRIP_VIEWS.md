# T3 그룹·여행 목록 화면 연결

범위: 기존 /next 개발 앱에 T2의 groups/trips 모델을 연결한다. 기획·목업을 수정하지 않고 기존 스타일을 재사용한다. 루트 경주 앱은 변경하지 않는다.

## 사용 흐름

1. /next/ 또는 #groups: 로그인한 계정의 그룹 목록. 로그인 전에는 시작 안내.
2. #group-create: Google 로그인한 리더가 그룹 생성.
3. #group/{id}: 같은 그룹의 진행 중 여행과 지난 여행을 구분해 조회.
4. #trip-create/{groupId}: 리더만 새 여행 생성. 여행명·목적지·기간·장소는 항상 빈 입력으로 시작. 장소 없이 생성 가능.
5. #trip/{groupId}/{tripId}: 여행 이름·목적지·기간·장소·기록 수 조회. 종료된 여행도 열람 가능.
6. #legacy와 기존 #room/#join/#create: 종전 공동 탐험방 흐름 보존.

리더 전용 생성 링크·폼은 멤버 화면에 넣지 않는다. 직접 경로로 새 여행 생성을 열어도 서버에서 확인한 역할이 리더가 아니면 입력 폼을 표시하지 않는다. 실제 쓰기 권한은 T2 서버에서 다시 검사한다.

## 새 여행과 중복 방지

새 여행 폼에 이전 여행의 장소·사진·소감·완료 상태를 복사하지 않는다. 응답 유실로 확인하지 못한 요청은 별도 안내에서 복구하며 폼에 이전 값을 자동 채우지 않는다.

서버 호출 전에 계정·작업 종류·그룹별 namespace에 요청 ID와 입력을 보관한다. 같은 입력 재시도는 같은 ID를 쓴다. 미확인 요청과 다른 입력의 새 생성은 기존 결과 확인 전 차단한다. 저장 공간 오류·손상된 요청은 조용히 새 ID를 만들어 호출하지 않는다. 브라우저 데이터 삭제 후의 복구까지 보장하지는 않는다.

비동기 읽기·생성 결과에는 계정과 화면 버전을 확인한다. 로그아웃·계정 전환·다른 화면 이동 뒤에 이전 계정의 응답이 화면을 다시 채우지 않는다. 권한 확인은 서버 조회로 수행하고 캐시만으로 리더 버튼을 노출하지 않는다.

## 검증

- 로컬 npm test: 14개 통과. 기존 앱·패키징·재시도·요청 격리·저장 실패·손상 데이터 차단 포함.
- tests/groups-browser.mjs: demo Auth/Firestore와 실제 exported callable handler를 연결해 모바일 크기 Chromium에서 목록→그룹→여행 생성, 빈 새 여행, 장소 0개, 종료 이력, 응답 유실 후 중복 없는 복구, 멤버 버튼/직접 경로 차단, 로그아웃 격리를 검사한다.
- 브라우저 CI 추가는 GitHub 토큰 workflow 권한 부족으로 업로드가 거부됐다. 워크플로 변경은 분리하고 기존 CI를 유지한다. 로컬 브라우저 실행과 원격 기존 CI 결과를 구분해 PR에 보고한다.
- 실제 Google 팝업·운영 Firebase·물리 iOS/Android·한글 폰트의 시각 품질 검증은 아니다.

## 이번에 연결하지 않은 것

그룹 초대(T6), 여행 하단 4탭(T7), Google Places 검색(T4), AI 문구(T5), 사진/스탬프 화면(T8), 기록 피드(T9), 종료 동작·리포트(T10)는 후속이다. 이번의 종료 이력 화면은 저장된 closed 상태를 조회하며 종료 버튼은 추가하지 않는다. 운영 배포·결제·데이터 이전·사용자 승인 없는 main 병합을 수행하지 않는다.
