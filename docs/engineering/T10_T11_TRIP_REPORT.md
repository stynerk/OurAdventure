## 리포트와 권한

종료 여행의 기존 4탭 헤더에서 리포트로 이동한다. 리더·그룹 멤버 모두 `getTripReport`를 호출할 수 있고 서버는 인증·현재 멤버십·종료 상태를 확인한다. 진행 중 여행과 비멤버는 거부한다.

리포트는 기간(시작·종료·포함 일수), 장소 수, published 사진 수, 개인별 도장 합계/가능 도장 수, 멤버별 도장, 장소별 최신 대표 사진 1장, 한 줄 느낌 모음이다. 자유 기록도 사진 수·느낌에 포함한다. 미확정/삭제 기록은 제외하고 같은 멤버·장소의 여러 사진은 도장 1개다. 도장은 실제 published 사진에서 도출하며 같은 별칭의 서로 다른 UID를 합치지 않는다. 모든 published 기록을 집계하므로 피드의 12개 페이지 제한 때문에 총계가 줄지 않는다.

대표 사진이 없는 장소는 빈 상태를 표시한다. 파일 읽기 실패는 안내를 표시하고 나머지 리포트 집계는 유지한다. 사진은 인증된 Storage 읽기로 받아 Blob URL로 표시하며 화면/그룹/계정 전환과 로그아웃 시 해당 URL을 정리한다.

## 리더용 이미지

`configureShareImage`는 현재 그룹 소유자 및 owner 역할·멤버십·여행 종료를 서버 트랜잭션에서 검사한다. 멤버는 리포트를 볼 수 있지만 결과 구성 UI가 없고 직접 callable 요청도 거부된다. 다운로드 직전에도 같은 구성 요청으로 권한을 다시 검사한다.

사진은 확정된 기록 중 1~6장을 순서대로 고른다. 피드 1080×1350, 스토리 1080×1920과 그리드/도장판을 조합한다. 도장판의 장소는 01~10 번호로 표시하고 장소명은 내보내지 않는다. 기본 문구·별칭·사진/도장 숫자 외에 여행명·그룹명·목적지·장소명·느낌·이메일·UID·파일 경로를 이미지 텍스트로 넣지 않는다. 사진 전체가 캔버스에서 다시 그려져 원본 EXIF/텍스트 메타데이터를 복사하지 않는다.

서버 구성은 `shareImages`의 요청별 문서에 저장하고 같은 requestId/구성은 재사용한다. Firestore 직접 읽기/쓰기는 기본 차단을 유지한다. 반복 요청도 현재 권한·사진의 published 상태와 경로/세대를 재검사한다. 서버가 확정한 사진/별칭/도장 정보만 렌더러에 전달하고 클라이언트의 임의 제목·장소·크기·역할은 사용하지 않는다. 종료 이후 허용하는 쓰기는 이 결과 구성 메타데이터이며 사진·느낌·도장 작성/수정/삭제 차단은 유지한다.

선택 사진의 메타데이터·세대·최대 5MiB를 확인하고 모두 내려받아 디코딩한 다음 PNG를 만든다. 24MP 초과 사진은 이 브라우저 렌더 단계에서 거부한다. 일부 로딩 실패나 디코딩 실패를 빈 칸으로 대체해 저장하지 않는다. 실패 시 선택을 유지하고 재시도한다. 0장·미리보기 미완료·사진 내용 확인 전에는 저장할 수 없다. 선택/형식/템플릿이 바뀌면 기존 미리보기와 저장 가능 상태를 폐기한다.

네이티브 크기로 한 번 생성한 PNG Blob을 미리보기 `<img>`와 다운로드에 함께 사용한다. 저장할 때 캔버스를 다른 배율로 다시 그리지 않는다. 파일명은 `our-adventure-{grid|board}-{feed|story}.png`로 고정해 여행명/계정 정보를 넣지 않는다.

별칭 외 개인정보·위치의 자동 텍스트 삽입과 EXIF 전파는 차단한다. 사진 픽셀 자체의 얼굴·문서·주소·표지판을 자동 인식/마스킹하는 기능은 아니다. 리더가 선택 사진에 해당 정보가 드러나지 않는지 확인한 뒤 저장해야 한다. 얼굴/위치 자동 제거까지 검증했다고 보고하지 않는다.

## Analytics

PM `docs/ANALYTICS_SPEC.md`(docs/analytics-spec)를 확인했다. `report_view`는 공통 파라미터만, `share_image_create`는 format/template/photo_count 구간, `share_image_save`는 format/template/result=ok|error를 허용한다. 생성은 사진 디코딩과 PNG 생성 이후, 저장 성공은 브라우저 다운로드 시작 이후에 기록한다. OS의 실제 파일 저장·사용자 취소까지 확인하는 이벤트는 아니다. 별칭·사진·느낌·계정/장소/선택 사진 ID를 보내지 않는다. 에뮬레이터 실제 GA 전송은 끄고 테스트 수집 대역 및 실제 필터 단위 테스트로 확인한다.

## 검증 실행

`npm test`는 단위·계약·패키징을 실행한다. Windows의 프로세스 메모리 부족을 줄이기 위해 테스트 파일을 순차 실행하며 파일 안의 동시 요청 검증은 유지한다. `npm run test:reports`는 demo Auth/Firestore/Storage에서 Storage/권한 통합, 그룹/기존 Room, 실제 SDK·그룹 Chromium 회귀, 리포트/PNG Chromium 시나리오를 순서대로 수행한다. Java 21·Playwright Chromium·Node 22 이상이 필요하다.

로컬에서는 기존 작업공간 Java·브라우저·Firebase 13.0.0 공식 SDK 캐시를 재사용한다. 제한된 JVM 메모리와 `-Xint`·Chromium 메모리 설정은 테스트 환경에만 적용한다. 실제 Storage/API 권한을 모의 응답으로 바꾸지 않는다. Firebase의 bounded `getBlob`이 내부 Blob.slice로 MIME을 비우는 동작은 메타데이터와 실제 크기를 확인한 뒤 MIME을 복원해 처리한다.

실행 결과·원격 CI·스크린샷·앱에서 저장한 PNG 예시는 PR에 기록한다. 테스트용 사진·별칭·PRIVATE 표식은 모두 합성 자료이며 실제 이용자의 기록은 사용하지 않는다.

로컬 단위 35개, Firestore/Room 37개, 실제 Storage/T9 통합 10개, 실제 SDK·그룹 Chromium 전체 회귀가 통과했다. 리포트/PNG Chromium 전체도 통과했으며 도장판 여백 보정 후 같은 시나리오를 재실행해 네 PNG 조합의 SHA-256/크기·실패 차단·현재 권한 확인을 최종 검증했다. 초기 병렬 단위 실행의 메모리 부족 및 Windows 프로세스 종료가 있었고 최종 순차 단위와 제한 메모리 실행은 종료 코드 0이었다.
