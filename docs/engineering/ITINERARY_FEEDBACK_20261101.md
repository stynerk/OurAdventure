## 데이터·실패 처리

- 여행 일정 상한을 전체 10개에서 60개로 확장했다. 사진·스탬프는 기존 장소 ID에 유지한다. 대량 가져오기는 기존 장소 연결/명시적 새 일정 선택, 이름이 유일할 때의 자동 연결만 허용한다. 이름 중복이 모호하면 선택을 요구하며 묵시적으로 새 장소를 추가하지 않는다.
- 가져오기는 병합이다. 원본 장소·다른 사람의 사진·완료를 자동 삭제하지 않는다. 신규 요청 ID와 itineraryRevision/장소 revision으로 재시도·다른 화면 수정을 검사한다. 확정 전 임의 AI 결과가 DB를 수정하지 않는다.
- 응답 유실 시 반영 요청을 계정·그룹·여행별 localStorage에 보존하고 같은 요청으로 재시도한다. 확정 오류에는 편집을 다시 허용한다. 파일 원본은 서버/Storage에 보관하지 않으며 문서 선택·내용은 현재 화면에 유지한다. 문서 원본의 새로고침 후 복구는 제공하지 않는다.
- 일차 범위, HH:MM, 종료>시작, 필수 이름·개수는 서버에서 검사한다. AI의 잘못된 시간은 초안 경고와 빈칸으로 반환하고 사용자에게 확인받는다. 불명확한 일정은 임의 장소나 시각으로 채우지 않는다.
- 종료 여행·비리더·비멤버의 편집/반영은 서버에서 거부한다. v2GroupSecrets/초대 원문·분석 사용량은 클라이언트에서 직접 읽지 못한다.
- 10개를 넘는 장소의 결과 이미지 도장판은 극도로 작은 원형 도장 대신 멤버별 완료 개수로 표시한다. 기존 10개 이하 형식은 유지한다. Analytics의 place_index 허용 범위도 1~60으로 맞췄다.

## AI 활성화 조건

운영 Functions의 AI 모델 환경 설정을 확인하지 못했으며 작업 세션에도 AI 키·모델이 없다. Secret Manager 이름 조회는 403이어서 비밀이 없다고 단정하지 않는다. 실 AI 호출·새 결제 연결·유료 API 활성화를 하지 않았다.

활성화에는 오너가 선택한 파일/이미지 지원 모델, API 접근키, 사용 요금 승인이 필요하다. API 키는 채팅·저장소로 전달하지 않는다. Firebase Secret Manager에 OPENAI_API_KEY를 저장하고, 서버 배포 환경에서 ENABLE_ITINERARY_AI=true 및 OPENAI_MODEL을 설정하면 analyzeItinerary에만 비밀을 바인딩하도록 준비했다. 모델·한도·요금을 확인한 뒤 해당 함수 재배포와 실제 문서 품질 검사를 진행한다.

분석은 인증된 그룹 리더만, 파일당 4MiB, 텍스트 5만 자, 하루 10회, 출력 60개까지다. 유형/기본 시그니처/크기를 서버에서도 검사한다. 입력은 Responses API에 store:false로 보내지만 이것이 공급자의 모든 보관 정책을 0으로 만든다는 뜻은 아니다. 파일·본문을 앱 로그나 Analytics에 넣지 않는다. 암호화·손상·지원 밖 파일은 읽을 수 있다고 약속하지 않는다.
