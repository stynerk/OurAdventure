# T14 UI 리프레시

2026-10-28. PR #18 `fd8cdfe` 위 `engineering/ui-refresh`. [디자인 가이드](../../DESIGN_SYSTEM.md)(PR #19 `docs/design-system`)와 사용자 결정인 v2 톤 전체 적용·첫 화면 커버를 반영했다. Claude artifact URL은 도구로 열리지 않아 문서를 기준으로 구현했으며 캔버스와 픽셀 단위 대조했다고 주장하지 않는다.

## 적용

`/next`의 공통 색·Pretendard·간격·카드/버튼·3단계 그림자, Lucide 선 아이콘, 떠 있는 4탭, 3열 Clay 도장과 Jua 글씨, 자기 진행 카드, 지도 상단 바/다음 탐험 카드, 상세 커버/흰 시트, 실제 서버 확정 후 도장 획득 dialog, 추억 칩/사진 그리드/기록 메뉴, 리포트 요약과 인스타 빌더/PNG 색·글꼴을 통일했다. 실험 배지와 기존 탐험 링크는 프로필 메뉴에서 열 수 있다.

기존 인증·초대·정원·개인별 도장·업로드/확정·수정/삭제·종료·리포트 권한과 요청 데이터는 유지한다. 사진 선택은 보이는 카메라/앨범 버튼으로 숨긴 기본 입력을 열고, 칩은 기존 서버 필터 쿼리에 연결한다. 도장 획득 시트는 서버의 `newCompletion` 확인 뒤만 열리며 다음 장소 보기/사진 더 남기기/ESC로 닫을 수 있다. 결과 저장 전 권한 재확인·개인정보 제외와 미리보기 PNG Blob 재사용은 유지한다. 서버·Rules·데이터 모델·운영 설정과 루트 경주 앱은 변경하지 않았다.

## PR #21 PM 검토 반영

여행 화면은 브랜드 헤더와 반복 정보 카드를 제거하고 64px 상단 바(뒤로·여행 이름·종료 배지·리더 관리 아이콘) 하나로 정리했다. 종료 여행은 작은 `리포트` 링크로 결과를 연다. 긴 여행 이름은 한 줄로 줄여 표시하되 접근성 트리에는 전체 이름을 유지한다. 사진 저장 후 집계에 필요한 기록 수는 숨긴 데이터 요소로 유지한다.

지도는 상단 바 아래에서 화면 좌우·하단까지 이어지며 정보 카드가 지도를 덮지 않는다. 종료 여행에는 다음 장소 강조·반복 고리가 없고 미완료 핀을 회색으로 표시한다. 스탬프 화면의 바깥 흰 카드를 제거하고 3열 도장판을 유지했으며, 완료 도장 안에 미션의 스탬프 이름(Jua)을 표시한다. 이름이 없는 기존 장소는 장소 이름을 사용한다.

24장 캡처와 브라우저 검사를 다시 실행했다. 기존 접근성 검사에 상단 바 높이·본문 겹침, 지도 너비·하단 여백, 종료 핀 강조 제거, 도장판 카드 중첩·3열·Jua 이름 검사를 추가했다. 이 과정에서 320px 미디어 규칙이 지도에 카드 여백을 다시 넣는 문제도 수정했다. 단위 테스트 37개와 Auth/Firestore/Storage 실제 SDK·그룹/사진/추억/종료/리포트/PNG 브라우저 검사를 재검증했다. 아래 서버 통합 47개 로그는 T14 최초 검증 결과이며 이번 화면 수정에서 서버 코드를 바꾸거나 해당 서버 전용 테스트를 다시 실행하지 않았다.

## 커버와 사용 조건

[WebP](../../../next/assets/travel-cover-v2.webp) · [JPEG 대체](../../../next/assets/travel-cover-v2.jpg) · [생성 도구/정확한 프롬프트/사용 조건](image-generation.json) · [크기/해시](cover-metadata.json).

OpenAI 내장 `image_gen`으로 생성한 가상의 여행자·풍경이다. 실존 인물/랜드마크/브랜드를 지정하지 않았고 얼굴은 뒷모습, 아래쪽은 단순한 공간이다. 생성 원본은 780×2017이며 요구 출력에 맞춰 리샘플·크롭했다. 배포 파일은 **1170×2532**, WebP 품질80 **192,440바이트**, JPEG 품질80 **262,381바이트**다. 원본 자체가 1170px 이상이었다고 주장하지 않는다. 장식 이미지라 빈 alt를 사용하며 초대/목록/상세의 장식 커버에도 재사용한다. 실제 장소 사진으로 공급받은 자료는 아니다.

상업용 웹앱 사용은 적용되는 [OpenAI 서비스 계약](https://openai.com/policies/services-agreement/)·정책 준수를 전제로 한다. OpenAI와 고객 사이에서 출력물 권리를 고객에게 귀속시키는 조항을 근거로 사용하며, 별도 스톡 사진 라이선스는 사용하지 않았다. 독점성·법률상 저작권 보호를 보장한다는 뜻은 아니다. Pretendard/Jua는 SIL OFL, Lucide static 1.62.0은 ISC이며 [동봉 라이선스](../../../next/assets/)를 유지한다.

## 접근성 보정과 검증

가이드 주황 `#D9411E`와 흰 글자의 대비는 4.44:1이어서 행동색을 가까운 **`#D63E1B`**로 보정했다. 보조색도 회색 앱 바탕에서 4.5:1을 확보하도록 `#626A79`로 사용한다. 밝은 숫자색을 작은 본문에 쓰지 않는다. 로그인은 어두운 scrim, 버튼·링크 44px 이상, 명시적 라벨/포커스, 색 외 완료 글자·체크, reduced motion 대체를 적용한다.

`npm test`: **37개 통과**(기존35 + UI 대비/에셋2). Pages 패키징에서 새 UI 모듈·커버·글꼴 복사와 비공개 서버/설정 제외도 확인한다. 실제 Storage 10·그룹24·Room13 = **47개 통합 통과** 후, 바뀐 UI에 대해 실제 Auth/Firestore/Storage SDK·callable HTTP와 그룹/사진/추억/종료/초대·리포트 Chromium 전체를 재실행해 종료 코드0을 확인했다. 물리 기기나 운영 Functions 인프라 검증은 아니다.

`tests/ui-audit.mjs`는 아래 8개 화면 각각 320/375/390px에서 문서 가로 넘침, 보이는 터치 대상44px, 제어 글자 잘림, 이모지 장식/기본 파일 입력 비노출, reduced motion, axe-core의 대비·버튼/링크 이름·입력 라벨·이미지 alt를 검사한다. 전체 접근성 인증을 뜻하지 않는다. 스크린샷은 모션을 줄인 안정 상태로 저장한다. 실제 앨범 버튼의 파일 선택 창과 장소/사람 칩 클릭도 검사했다. 결과 이미지 5개(두 템플릿×두 크기 + 여행 이름)의 미리보기/다운로드 SHA-256·크기·메타데이터 제외, 빈 사진/읽기 실패 차단·저장 직전 비리더 거부를 재검증했다.

실행: `npm run test:reports`(기존 전체), UI 집중 재검증은 demo Auth/Firestore/Storage에서 `UI_AUDIT=1`, `UI_AUDIT_AXE_PATH=<axe.min.js>`를 지정해 `node tests/ui-verify.mjs`. Windows 로컬은 작업공간의 Java21·Chromium·공식 Firebase13.0.0 SDK 캐시와 별도 검증 도구를 사용한다. 앱 의존성 버전·lockfile은 변경하지 않았다. UI UX Pro Max의 지침·품질 항목을 적용했으며 Python DB 검색 결과를 사용했다고 보고하지 않는다.

초기 검증에서 작은 링크 대상·숨겨진 종료 안내를 수정했고, 장식 SVG 공백으로 인한 숫자 비교와 axe의 내부 캔버스가 PNG 텍스트 spy에 섞이는 테스트 문제도 고쳤다. PNG 전용 캔버스만 검사하며 개인정보 제외 검증을 삭제하지 않았다. 최종 [브라우저 로그](verification.log), [서버 통합 로그](integration.log), [화면별 지표](audit.json)를 참조한다. 모든 화면 자료는 합성 사진/별칭/여행이며 실제 이용자 데이터나 초대 토큰을 스크린샷에 쓰지 않았다.

## 남은 확인

실기기 Safari/Android의 카메라·다운로드·동적 글자 확대와 safe area, 운영 OAuth/Storage/GA는 후속이다. [QA #20](https://github.com/stynerk/OurAdventure/pull/20)의 추천/AI·목적지 초기화 미구현 사항은 이 UI 작업으로 구현한 것으로 취급하지 않는다. 장소 추가·삭제는 [T15 후속](../T15_PLACE_EDIT.md)에서 구현·검증한다. 현재 장소 모델에 일차·장소 사진이 없어 코스는 기존 장소 순서이며 상세/목록 사진은 공통 장식 커버다. 그룹 목록도 개별 완료 집계를 새로 읽어 가상의 진행률을 만들지 않는다. 실제 데이터가 준비되면 해당 부분은 후속 디자인 검토가 필요하다. 생성 커버의 더 큰 네이티브 원본과 폰트 전송량/실제 망 성능은 후속 개선 여지다.

머지·사이트/Functions/Rules 배포·결제·운영 권한 변경은 수행하지 않았다. T12 재QA를 위한 Draft PR이다.
