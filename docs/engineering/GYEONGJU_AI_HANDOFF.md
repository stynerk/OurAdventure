## 2. 경주 여행을 구성한 의도

- 주 사용자는 초등학교 2학년 아이, 부모는 진행을 돕는 사용자였다.
- 아이에게는 탐험, 부모에게는 진행 장치, 가족에게는 기록을 제공하려 했다.
- 동화 지도 → 짧은 관찰 → 사진 아이디어 → 스탬프 보상 → 가족 원정기로 이어졌다.
- 짧은 문장·큰 터치 영역·시각 우선·3~5분 행동과 빠른 보상이 당시 원칙이었다.
- 장소 목록뿐 아니라 식사·짐 보관·이동·휴식도 전체 일정에 포함하되 스탬프를 강제하지 않았다.
- 장소 순서를 바꾸거나 건너뛰어도 페널티가 없었다.
- 사용자는 이번 대화에서 기존 가족여행 서비스를 아이가 좋아했다고 설명했다. 개별 장소·미션별 만족도 수치나 원본 설문은 확인하지 못했다.

## 3. 코스 구성 사례: 3일·9개 스탬프

모두 역사적 계획·앱 콘텐츠다. 장소의 현재 운영·촬영·예약 조건을 확인한 목록이 아니다.

| 일차 | 장소 / ID | 스탬프 이름 | 당시 사진 아이디어 요약 |
|---|---|---|---|
| 1 | 대릉원 / daereungwon | 왕의 언덕 | 봉분을 배경으로 손 왕관 |
| 1 | 첨성대 / cheomseongdae | 별 관찰자 | 손가락 네모 프레임에 창 넣기 |

일부 구형 문서의 ‘9개·4+4+1’ 요약 목록에는 동궁과 월지가 빠져 있다. 위 목록은 실제 소스의 9개 객체를 기준으로 보정했다.

### 동선의 의도

1. 첫날: 시내 유적을 도보로 연결. 대릉원·황리단길 → 첨성대 → 월성·석빙고 → 저녁 → 동궁과 월지 야경.
2. 둘째 날: 불국사·석굴암을 오전에 묶고 → 점심 → 공예 체험 → 보문 휴식 → 저녁 → 월정교 야경. 차량 이동·주차·시내 복귀가 필요했다.
3. 마지막 날: 체크아웃 → 박물관 → 성동시장 점심·기념품. 귀경에 앞서 현지 일정은 짧게 구성.

서울 왕복 이동은 당시 앱 범위에서 제외했다. 9개 전체를 일반적인 모든 가족여행에 강제하지 않는다.

## 4. 재사용 시 반드시 분리할 정보

- **지연 도착:** 인계 문서에는 실제 대화에서 첫날 15:30 도착·첨성대 시작으로 바꾼 내용이 있다고 적혀 있다. 앱의 11:30 점심·13:30 대릉원 고정 일정과 다르다. 추천 동선은 도착 시간·피로도에 따라 재편집할 수 있어야 한다는 근거로만 활용한다.
- **예약·휴관:** 공예 예약과 어린이박물관 일정은 문서/이전 대화 요약 사이에 충돌이 있다. 당시 코드의 ‘미확정’, ‘휴관’ 표기를 현재 사실이나 사용자의 확정 예약으로 복사하지 않는다.
- **삭제된 코스:** 김유신 장군 동상(kimyusin), 김유신 묘(kimyusin-tomb), 경주읍성(eupseong)은 종전 코스의 기록을 보존하는 경로가 있다. 해당 장소를 실제 방문했다는 개별 사용자 데이터는 이번에 확인하지 않았다.
- **예시 추억 문장:** quests의 memory와 마이그레이션 기본 문장은 앱이 제공하는 문구다. 사용자가 직접 쓴 후기·실제 수행 결과로 다루지 않는다.
- **브라우저 기록:** gj-family-quest의 done/photos/memories/archivedRecords와 gj-family-diary-template의 일기 초안은 브라우저 로컬 데이터다. 저장소 소스만으로 내용·완료 여부를 알 수 없다. 이번 작업은 읽거나 변경하지 않았다.

## 5. AI 코스 구성에 넘길 체크 항목

다음은 경주 사례에서 도출한 구현·기획 검토 제안이며 확정 정책과 구분한다.

1. **입력 후보:** 목적지, 여행 기간, 첫날 도착·마지막 날 출발 시각, 이동 수단, 동행 구성·아이 연령, 관심사, 확정 예약, 필수/제외 장소. 부족한 입력에서 임의의 예약·숙소·가족 연령을 만들지 않는다.
2. **장소 묶음:** 인접 권역을 같은 날짜에 묶고 식사·이동·휴식 여유를 고려한다. 검증되지 않은 소요 시간·최적 경로를 사실로 표시하지 않는다.
3. **장소와 일정 구분:** 사진 스탬프 대상 장소와 식사·휴식·이동 블록을 구분한다. 모든 일정에 스탬프를 만들 필요는 없다.
4. **기본 스탬프:** 장소명·아이콘·표시 순서와 선택적 이름을 구성하되, 현재 사진 기반 개인 완료를 유지한다. 옛 관찰 미션·이야기 생성은 참고 콘텐츠이며 자동으로 MVP 범위에 추가하지 않는다.
5. **수정 후 확정:** AI가 여행을 바로 생성하지 않고 리더가 장소 삭제·추가·순서를 조정한다. 목적지를 바꾸면 이전 목적지 초안이 섞이지 않아야 한다.
6. **빈 새 여행:** 같은 그룹·멤버를 재사용해도 새 여행의 사진·소감·개인 완료·퇴역 기록은 빈 상태다. 참고 사례와 사용자 이력은 자동 복사하지 않는다.
7. **정보 검증:** 현재 영업·휴관·가격·예약·촬영/접촉 허용 여부는 외부 근거로 확인할 항목이다. AI가 빈칸을 확정 문장으로 채우지 않는다.
8. **결과의 역할:** 추천 초안과 실제 방문·개인 완료 기록을 구분한다. 종료된 과거 여행은 원래 기록대로 보존한다.

## 6. 기획 담당자가 검토할 결정

- 목적지만 입력하는 빠른 생성과, 기간·이동 수단·아이 동반을 받는 상세 생성의 범위.
- 식사·휴식·이동도 AI 결과에 포함할지, 첫 버전은 스탬프 장소만 생성할지.
- 사진 아이디어·스탬프 이름까지 AI가 만들지, 기본 템플릿으로 유지할지. 관찰 미션·스토리 생성은 별도 판단.
- 실제 예약·운영시간 확인을 어느 단계에서 어떤 출처로 할지.

## 7. 기계 판독용 참고 자료

[경주 코스 참조 JSON](../../development/reference/gyeongju-course.json)에 앱 소스의 장소·날짜별 순서·기본 스탬프·사진 아이디어·현지 시간표를 추출했다. provenance와 historical_plan_only 표시를 유지한다. 사진 URL·기본 memory·사용자의 사진·완료 상태는 넣지 않았다.

재생성: `node development/extract-gyeongju-reference.cjs`. AI 생성 API의 프롬프트에 이 파일을 자동 투입하는 변경은 수행하지 않았다. 기획 검토 후 적용한다.
