# T6 그룹 초대·별칭 참여

기준: PRD v2 F3, AC-3a/3b/3c. 브랜치 `engineering/group-invite`, 기준 PR #8 `engineering/group-trip-views`. 기존 Room과 루트 경주 앱은 유지한다.

## 구현

- `createGroupInvite`: Google 인증된 그룹 리더만 생성·재발급한다. 서버가 만든 256비트 무작위 토큰을 한 번 반환하며, 서버 전용 `v2Invites`에는 해시 키와 그룹 참조만 저장한다. `v2GroupSecrets`의 현재 해시와 일치해야 사용할 수 있다. 원문 토큰은 DB에 보관하지 않는다.
- 재발급 트랜잭션은 이전 초대 문서를 지우고 현재 해시를 교체한다. 기존 멤버·여행·기록은 건드리지 않는다. 응답이 유실되면 다시 발급하면 된다. 이전 링크는 신규 참여에 사용할 수 없지만 기존 멤버는 내 그룹에서 계속 접근할 수 있다.
- `previewGroupInvite`: Firebase 인증 후 유효성·현재 링크·정원·기존 멤버 여부를 서버에서 확인한다. 신규 참여자에게는 유효하고 자리가 있을 때만 그룹 소개 이름을 보낸다. 잘못된 링크는 `{state:invalid}`, 정원 초과는 `{state:full}`만 반환하며 그룹 ID·이름·여행·멤버 정보를 포함하지 않는다. 기존 멤버는 정원이 차도 자신의 그룹으로 이동할 수 있다.
- `joinGroup`: 같은 트랜잭션에서 현재 초대, 그룹, 인증 UID의 멤버 문서를 읽는다. 기존 UID면 별칭을 덮어쓰거나 인원을 늘리지 않고 재입장한다. 신규 UID면 리더 포함 10명 상한을 검사한 뒤 멤버 문서·memberIds·memberCount를 함께 갱신한다. 클라이언트가 보낸 UID·역할·정원·그룹 ID는 신뢰하지 않는다. 별칭은 공백 제거 후 1–24자다.
- 기존 보안 규칙의 전체 기본 거부를 유지한다. 초대·비밀 문서도 리더를 포함한 웹 클라이언트가 직접 읽거나 쓸 수 없다. 실제 그룹·여행 열람 권한은 가입 트랜잭션 성공 후에만 생긴다.

## 화면

리더 그룹 상세에 초대 링크 생성·재발급 및 복사 버튼을 추가했다. 링크는 `#group-join/{token}`으로 열리며, 멤버는 익명 인증을 내부적으로 생성한 뒤 별칭만 입력한다. 다른 기기·로그아웃·브라우저 데이터 삭제 시 익명 기록 복구가 어려운 점을 화면에서 안내한다.

동일 브라우저의 기존 멤버는 링크를 다시 열면 바로 그룹으로 이동한다. 별칭이 같은 다른 UID는 별개의 멤버다. 다른 기기에서 자동으로 동일인을 판별하는 기능은 없다.

잘못된 링크와 정원 초과 안내는 구분한다. 소개를 본 뒤 마지막 자리가 차는 경우도 가입 실패 시 소개·별칭 폼을 모두 지워 그룹 내용이 남지 않는다. 비동기 응답은 현재 계정·화면 세대 확인 후에만 반영한다.

## 검증 항목

- AC-3a: 9명에서 서로 다른 UID 두 개가 동시에 가입하여 성공 1건·정원 초과 1건, 최종 멤버 문서/배열/인원 모두 10.
- AC-3b: 같은 UID의 동시 가입 5건에서 신규 가입은 1건. 정원 10명 이후 재입장도 중복·별칭 변경 없음.
- AC-3c: 잘못된 형식·존재하지 않는 링크·재발급된 링크·정원 초과 응답에 그룹 내용 없음. 실패한 참여자의 직접 그룹 조회도 거부.
- 추가: 다른 리더·멤버의 초대 생성 거부, 원문 토큰 DB 미보관, 초대/비밀 문서 직접 읽기·조작 거부, 동일 별칭의 UID 분리, 재발급 후 기존·후속 여행 접근 유지.
- 브라우저: 링크 생성·클립보드 복사 → 익명 별칭 가입 → 재입장, 권한에 따른 버튼 제외, 소개 이후 정원 초과 시 내용 제거, 새로고침 정원 초과, 잘못된/재발급 링크, 로그아웃.
- PR #8 헤더: 320px·390px에서 브랜드와 배지의 사각형이 겹치지 않고 가로 넘침이 없는지 검사한다.

실행 결과: 로컬 단위·계약·패키징 15개, Firestore 트랜잭션·보안 규칙 29개 모두 통과. 실제 SDK 3세션 및 위 브라우저 전체 시나리오도 통과했다. 테스트는 demo Auth/Firestore 에뮬레이터와 headless Chromium, 실제 Firebase SDK·export된 callable HTTP handler로 수행했다. 실제 Google OAuth, 운영 Cloud Functions 배포, 물리 iOS/Android, GA 수신은 이 테스트에 포함되지 않는다.

## 남은 범위

공개 배포·main 머지는 수행하지 않는다. 실서비스 Anonymous/Google Auth와 함수 배포는 운영 연결 시 확인한다. 별칭 변경·탈퇴·강퇴·초대 만료와 계정 간 기록 복구는 이번 범위에 포함하지 않는다. GA 이벤트는 별도 PR #11 및 명세 PR #10과 통합할 때 연결해야 한다. 기존 계정에서 새 기기에 익명 참여하면 다른 UID로 정원에 포함된다.
