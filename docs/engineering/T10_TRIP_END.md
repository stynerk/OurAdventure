# T10 일부: 여행 종료·읽기 전용

2026-10-28 사용자 요청 범위. 브랜치 `engineering/trip-end`, 기준 PR #13. 리포트와 인스타 이미지는 제외한다.

## 서버와 화면

- `endTrip(groupId,tripId)` callable은 인증 UID의 그룹 멤버 문서·그룹 소유자·여행을 서버 트랜잭션으로 확인한다. 클라이언트의 ownerId/closedBy를 신뢰하지 않는다. 비리더·비멤버는 거부한다.
- 진행 중 여행을 `closed`로 바꾸고 서버 시각 `closedAt`과 인증 UID `closedBy`를 저장한다. 이미 종료됐다면 동일 상태를 반환하며 시각을 다시 쓰지 않는다. 응답 유실 후 재시도와 중복 클릭이 종료 시각을 변경하지 않는다.
- 기존 사진 확정 경로와 장소 추가 경로가 트랜잭션 안에서 여행 상태를 읽으므로 종료 후 새 쓰기를 거부한다. 검증이 먼저 시작된 사진도 종료 이후 DB 확정을 할 수 없다. 종료와 사진 확정이 동시라면 직렬화 순서에 따라 종료 전 저장만 허용한다.
- 이미 완료된 같은 요청의 재시도는 기존 결과를 반환할 수 있으나 새 기록·완료·개수 변경은 발생하지 않는다. 기존 Firestore Rules는 리더를 포함한 클라이언트의 직접 기록/완료 쓰기와 status 재개 조작도 거부한다.
- 진행 중 여행의 리더 관리 화면에 확인 절차가 있는 여행 종료 버튼을 연결했다. 취소하면 상태를 유지한다. 서버 응답 성공 후 읽기 전용 지도로 이동한다. 멤버에게는 종료 버튼이 없고 직접 서버 요청도 거부한다.
- 종료 여행은 양 역할 모두 지도·코스·스탬프·추억을 열 수 있다. 관리·사진·스탬프 작성 컨트롤을 표시하지 않는다. 종료 여행 관리 주소 직접 접근도 읽기 전용 지도로 표시한다. 그룹 자체는 종료하지 않으며 초대와 새 여행 재사용은 유지한다.
