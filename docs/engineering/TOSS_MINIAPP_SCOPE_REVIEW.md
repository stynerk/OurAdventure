# 토스 미니앱 우선 검증 — 개발 검토

2026-10-30. 사용자: 지인 파일럿보다 토스 미니앱을 빠르게 출시해 반응을 확인하는 방향에 동의. 사업자 보유는 사용자 확인 사항이며 앱인토스 사업자 등록·심사 완료를 뜻하지 않는다.

이 문서는 테크 리드의 구현 차이·선행 작업 검토서다. PRD·화면 목업은 PM 담당이며, 기존 [PRD v2](../PRD_V2.md)를 직접 수정하지 않는다. 제품 코드 변경·미니앱 등록·심사 제출·출시를 수행한 문서가 아니다.

## 동의한 방향

목적지·기간·여행 취향 선택 → 추천 코스 확인 → 장소 교체·순서 변경 → 저장·동행자 공유 → 여행 중 사진으로 개인 스탬프 획득에 집중한다. 리포트·인스타 이미지 등은 첫 토스 버전의 주력에서 뒤로 둔다. 기존 웹의 해당 기능이나 여행 기록을 삭제한다는 결정은 아니다.

코스 저장·공유·여행 시 재방문으로 반응을 본다. 이전의 지인 2가족 완주를 토스 첫 출시의 모집 조건으로 삼지 않는 방향이다. 목표 수치·관찰 기간·출시 판정은 아직 확정하지 않았다. 토스 출시가 대규모 자연 유입을 보장한다고 가정하지 않는다.

## 코드 기준 차이

| 영역 | 현재 상태 | 토스 첫 버전에 필요한 작업 |
|---|---|---|
| 앱 | `/next`의 정적 HTML/CSS/모듈, GitHub Pages | 공식 WebView SDK·번들 방식으로 토스 안에서 렌더링. 기존 웹 URL로 이동시키는 래핑 방식은 사용하지 않음 |
| 인증 | `next/app.js`의 Google 팝업; `functions/group-service.cjs`가 생성·초대 시 google.com provider 검사 | 공식 토스 인증/서버 검증 경로 결정 후 Firebase UID와 연결. 클라이언트가 보낸 별칭·식별키만 믿어 리더 권한을 주지 않음. 기존 Google 사용자와 자동 병합하지 않음 |
| 추천 코스 | 목적지·날짜·수동 장소 입력. 기존 QA B2/B3/B6/B7/B8/B9 미완료 | 실제 장소 출처·후보 추천·날짜별 배치·교체·정렬·미리보기/확정 구현. 현재 코드를 추천 엔진 완성본으로 설명하지 않음 |
| AI | 관찰 미션·스토리용 기획 가이드 존재, 운영 생성 미구현 | 장소를 AI가 지어내지 않는 기존 하이브리드 원칙 유지. 모델·요금·횟수는 별도 결정, 미션 실패 시 장소 유지 |
| 저장·멤버 | 재사용 그룹/여행, 최대 10명, 본인 스탬프, 서버 권한·멱등성 구현 | 화면에서 그룹 생성 절차를 얼마나 드러낼지 PM 결정. 내부 모델은 재사용하되 토스 인증에 대한 권한 회귀 검사 |
| 초대·공유 | 웹 해시 URL·브라우저 클립보드 | 공식 미니앱 공유·진입 경로 및 초대 복원. 공유 버튼 실행과 실제 참여 완료를 구분 |
| 사진 | Storage 업로드·서버 확정 후 완료, 실패 시 요청/입력 보존 | 토스 샌드박스와 실제 iOS/Android에서 촬영·앨범·권한 거절·업로드·복구 확인 |
| 연결 | 웹용 Firebase 설정·인증 도메인·Storage CORS | 실제 발급된 토스 테스트/운영 origin에 대해 필요한 연결만 검증. 임의 도메인·와일드카드 허용 금지 |
| 화면 | 웹 헤더·뒤로가기·4탭 | 토스 공통 내비게이션·뒤로가기 연결, 자체 뒤로가기 중복 방지 |
| 로딩 | PR #24 읽기 복구, #25 원형 로딩 표시 | 토스 WebView에서 로그인→추천→저장→공유→사진 기록을 새로고침 없이 연속 검증. 스피너 표시만으로 성공 판정하지 않음 |

## 구현 순서 제안

1. PM이 토스 첫 버전 PRD·목업과 실패 상태를 확정한다. 기존 Google 로그인을 유지할지 토스 식별로 바꿀지, 취향 항목, 코스 카드·날짜별 편집 동작을 결정한다.
2. 별도 기술 검증에서 토스 번들 실행·내비게이션·인증→Firebase 권한·사진 선택·공유 재진입을 샌드박스로 확인한다. 실제 여행 데이터는 이 검증에 복사하지 않는다.
3. 추천·교체·정렬·확정 저장을 연결한다. 미확정 코스 초안과 확정된 여행을 구분하고, 저장 재시도는 같은 요청 ID를 사용한다. 목적지가 바뀌면 기존 후보를 정리한다.
4. 실제 단말 연속 QA와 지표 수신을 확인한다. 이후 검토 가능한 번들·심사 자료를 준비해 오너에게 제출 여부를 확인한다.

개발 소요일과 검수 완료일을 현재 확정하지 않는다. 인증 방식·장소 공급/요금·기존 미구현 코스 기능의 범위를 확인한 뒤 견적을 낸다. 사업자 등록·약관 동의·결제/API 활성화·권한 변경·심사 제출·토스 출시는 필요한 시점에 오너 확인을 받는다.

## 측정안 — PM 검토용

| 지표 | 분자 / 분모 제안 | 주의 |
|---|---|---|
| 추천 성공률 | 후보 코스를 보여준 요청 / 추천 요청 | 실패·지연·빈 결과 포함 |
| 코스 저장 전환 | 서버 확정 저장 사용자 / 추천 결과를 본 사용자 | 저장 버튼 클릭을 성공으로 세지 않음 |
| 코스 편집 | 장소 교체·순서 변경 사용자 / 추천 결과 사용자 | 편집 필요성과 추천 만족도를 함께 해석 |
| 공유 실행 | 미니앱 공유 실행 사용자 / 저장 사용자 | 상대 수신·참여 완료와 구분 |
| 초대 참여 | 서버 가입 확정 사용자 / 유효 초대 진입 사용자 | 재진입·정원 초과 별도 구분 |
| 여행 시 재방문 | 예정 여행 기간에 다시 연 저장 사용자 / 해당 기간이 도래한 저장 사용자 | 날짜가 아직 오지 않은 여행은 분모에서 제외 |
| 실제 기록 | 사진 업로드+서버 확정 사용자 / 여행 시 재방문 사용자 | 개인 스탬프만 집계 |

기존 [Analytics 명세](../ANALYTICS_SPEC.md)의 개인정보 금지 원칙을 유지한다. 새 이벤트명·허용 파라미터·관찰 기간·핵심 전환 정의는 PM 확정 후 명세에 추가한다. 토스 식별키·UID·별칭·사진·한 줄·정확한 위치·초대 토큰을 분석 로그에 보내지 않는다. 개발/QA 트래픽을 서비스 성과와 분리한다.
