# Our Adventure — Phase 1 PRD v1.3 검토본

작성일: 2026-10-20 · 담당: Product Strategy · 상태: 제품·화면 검토용, 구현·출시 승인 아님.

## 1. 문서의 목적과 기준

가족·지인 여행의 공동 기록을 중심으로 Phase 1의 범위·사용자 행동·검증 기준을 통합한다.
기존 문서의 초기 학교 중심 요구보다 최신 1A → 1B → 1C 출시 순서를 우선한다.
이 문서는 상세 API·DB·캐시 구현 수단을 확정하지 않는다. Engineering이 대안을 제안한다.

| 구분 | 의미 |
|---|---|
| 승인 범위 | 사용자 결정에 근거한 제품 범위. 구현·실측 완료를 뜻하지 않음 |
| 신규 제안 | 와이어프레임·설계를 위한 권고. 사용자 정책 승인과 구분 |
| 미결정 | 외부 파일럿·비용·보관 약속 전에 별도 결정 필요 |

기준 문서: [기존 PRD](https://github.com/stynerk/OurAdventure/blob/main/docs/PHASE1_SHARED_ADVENTURE_SPEC.md), [제품 계약](https://github.com/stynerk/OurAdventure/blob/main/docs/PHASE1A_PRODUCT_CONTRACT.md), [인수인계](https://github.com/stynerk/OurAdventure/blob/main/docs/HANDOFF.md), [Firebase 기록](https://github.com/stynerk/OurAdventure/blob/main/docs/FIREBASE_SETUP.md).
연결 산출물: [와이어프레임 명세](PHASE1_WIREFRAMES.md) · [화면 검토용 HTML](wireframes/index.html).

## 2. 문제와 제품 가치

여행 구성원이 각자 남긴 사진·짧은 글이 흩어져 있어 함께 보거나 일기·앨범으로 정리하기 어렵다.
Our Adventure는 하나의 여행에서 기록을 함께 남기고 보는 공동 게시판과 리더의 정리·출력을 제공한다.
Quest·스탬프는 현장 참여를 돕고 기록과 연결한다. 사진 게시를 Quest 완료의 필수 조건으로 만들지 않는다.
사용자는 기존 가족 MVP에서 니즈를 확인했다. 외부 반복 사용·지불 의사·학교 수요는 검증되지 않았다.

| 사용자 | JTBD | 기대 결과 |
|---|---|---|
| 가족·지인 리더 | 여행을 열고 초대한 뒤 함께 남긴 기록을 정리하고 싶다 | 링크 초대, 기록 선택·순서 조정, 일기·앨범 출력 |
| 일반 구성원 | 복잡한 가입 없이 여행 중 사진·짧은 생각을 남기고 보고 싶다 | 별칭으로 참여, 공유 범위 확인, 빠른 게시·재열람 |
| 후속 교사 리더 | 현장학습의 개인 진행·제출을 정리하고 싶다 | 1C에서 별도 정책·가상 코드·보고서 검증 |

## 3. 단계와 제외 범위

| 단계 | 승인 범위 | 진입·완료 판단 |
|---|---|---|
| 1A 구현 주력 | 가족·지인 최대10명(리더1+구성원9), 활동공간1개당 여행·활동1건, 공동 기록·열람·리더 출력 | 권한·기록 신뢰·모바일·출력·보관/비용 정책 게이트 통과 |
| 1B 규모 검증 | 최대30명은 독립 세션 테스트 목표 | 동시 참여·업로드·탐색·동기화의 측정과 누출/누락 검증 |
| 1C 학교 파일럿 | 1B 통과 후 개인 진행·제출·가상 참여코드·리더 보고서 | 교사 사용성·학생 데이터·보관 정책 별도 확정 |
| Phase 2 | 코스·미션 제작 후보 | 고정 코스 제약과 제작 수요 검증 후 판단 |

1A에서는 학교 제출·보고서, 성적·출결, 복수 반/학년, 공동 관리자, 공개 갤러리, 결제를 제공하지 않는다.
동영상·원본 장기 보존·전체 복구 백업·익명 교차기기 복구·AI 요약·오프라인 작업 큐도 1A 필수가 아니다.
한 계정의 여행 생성 총수와 서비스 전체 동시 수용량은 Unknown이다. 30명 검증은 출시 한도 상향이 아니다.
영구 그룹 계층은 미승인이다. 사용자 화면은 ‘여행·공동 게시판’으로 설명하고 내부 모델 Room과 구분한다.

## 4. 사용자 여정과 정보 구조

리더: 내 여행 → Google 로그인 → 경주 코스 확인·여행 생성 → 링크 초대 → 기록 확인 → 출력 구성 → 일기·앨범 저장/인쇄.
구성원: 초대 링크 → 여행 소개·별칭 → 참여 → 게시판/탐험 → 글·사진 게시 → 함께 보기.
종료: 리더 영향 확인 → 새 참여·기록 변경 중지 → 정책상 허용된 열람·출력 → 정해진 보관 종료 처리.

| 화면 개념 | 핵심 내용 | 연결 FR |
|---|---|---|
| 시작·내 여행 | 기존 여행 재진입, 새 여행 만들기, 초대 참여 안내 | FR-01, FR-02 |
| 여행 생성 | 고정 경주 코스·여행명·공동 진행·정원 안내 | FR-01 |
| 링크 참여 | 여행 소개·별칭·정원/종료/초대 오류 | FR-02 |
| 공동 게시판 | 구성원 기록 목록·빈 상태·새 기록·기록 상세 | FR-03, FR-04, FR-05 |
| 탐험 | 기존 지도·코스·스탬프·추억 4탭 유지, 공동 게시판 진입 제공 | FR-06, FR-10 |
| 리더 출력 | 기록 선택·정렬·템플릿·실제 결과 미리보기 | FR-07 |
| 여행 관리 | 참여 현황·초대·여행 종료·보관 안내 | FR-08 |

경로명과 화면 분할은 구현 확정사항이 아니다. 와이어프레임은 기능·상태 검토를 위한 예시다.
리더에게만 정리·관리 동작을 제공하며, 참여자의 Google 로그인 세션을 익명 계정으로 덮어쓰지 않는다.

## 5. 기능 요구사항과 수용 기준

### FR-01 여행 생성·재진입 — 승인 범위

리더는 Google 로그인 후 고정 경주 코스와 여행명을 확인해 여행을 만든다. 리더도 정원에 포함한다.
리더는 자신이 만든 여행 목록에서 기존 여행에 재진입할 수 있다. 활동공간1개당 여행·활동1건이다.

| ID | 검증 시나리오·수용 기준 |
|---|---|
| AC-01a | Google 인증이 없는 생성 요청(익명 인증 포함)은 서버에서 거부하고 Google 로그인 후 재시도 경로 제공 |
| AC-01b | 생성 성공 후 리더 멤버십·여행이 일치하고 재접속 시 동일 여행을 찾을 수 있음 |
| AC-01c | 응답 유실·중복 클릭 시 중복 생성 방지 결과와 오류 상태를 확인 |

### FR-02 링크 초대·참여 — 승인 범위, 초대 수명은 미결정

구성원은 별도 로그인 UI 없이 링크·별칭으로 참여한다. 내부 인증과 여행별 멤버십을 적용한다.
별칭은 표시명이며 사용자 식별·권한 근거가 아니다. 익명 세션 소실 시 교차기기 복구를 약속하지 않는다.

| ID | 검증 시나리오·수용 기준 |
|---|---|
| AC-02a | 9명 상태에서 2개 독립 세션 동시 참여 시 최종 인원 최대10명, 초과 요청 명시 거부 |
| AC-02b | 동일 사용자 재시도·재접속 시 멤버십·정원 중복 계산 없음 |
| AC-02c | 잘못된/폐기된 링크·종료·정원 도달을 구분해 안내하고 게시글·사진 노출 없음 |

### FR-03 공동 게시판·기록 열람 — 승인 범위, 목록 정렬은 신규 제안

해당 여행의 구성원이 게시 완료된 글·사진·활동 기록을 함께 본다. 최신 게시순을 권고한다.
다른 여행 구성원·비구성원은 주소·객체 ID를 알아도 신규 열람 요청을 거부해야 한다.

| ID | 검증 시나리오·수용 기준 |
|---|---|
| AC-03a | 로딩·빈 목록·기록 있음·불러오기 실패 상태에 각 다음 행동 제공 |
| AC-03b | 두 기기에서 확정된 같은 기록을 보고 미완성 업로드는 공개되지 않음 |
| AC-03c | 별칭이 같은 두 작성자를 동일 소유자로 취급하지 않고 타 여행 접근 차단 |

### FR-04 글·사진 작성 — 승인 범위, 입력 상세는 신규 제안

짧은 글·사진·Quest 연결을 제공한다. 글만/사진만 허용하고 둘 다 없는 빈 게시를 거부하는 안을 권고한다.
게시 전 공유 대상과 리더 출력에 포함될 수 있음을 알리고 사진 미리보기·교체·취소를 제공한다.
글자 수·사진 장수·용량·해상도는 미결정이다. 예시 화면의 수치를 서버 계약으로 해석하지 않는다.

| ID | 검증 시나리오·수용 기준 |
|---|---|
| AC-04a | 사진 첨부 시 사진 준비와 게시 저장이 모두 확정돼야 ‘게시됨’. 글만 게시할 때는 게시 저장 확정 필요. 실패 시 내용 보존·재시도 제공 |
| AC-04b | 사진 실패 시 글만 자동 게시하지 않고 사용자가 사진 없이 게시할 때만 진행 |
| AC-04c | 중복 클릭·응답 유실 후 재시도로 중복 게시글·사진을 만들지 않음 |
| AC-04d | 저장소 미설정·지원 불가 형식·권한/한도 실패를 성공으로 표시하지 않음 |

### FR-05 수정·삭제·충돌 — 본인 관리 권한 승인, 상세 삭제 정책 미결정

여행 진행 중 리더·구성원 모두 자기 글·사진만 수정·삭제한다. 리더에게도 타인의 원본 수정·삭제 권한을 제공하지 않는다.
삭제한 기록은 게시판·새 출력에서 제외한다. 물리 삭제·복구·기기 사본 범위는 정책으로 별도 설명한다.

| ID | 검증 시나리오·수용 기준 |
|---|---|
| AC-05a | 타인의 수정·삭제 요청은 서버에서 거부. 리더의 출력 순서 변경은 원본에 영향 없음 |
| AC-05b | 사진 교체 실패 시 기존 기록·사진 유지. 두 탭 수정 충돌을 무음 덮어쓰기하지 않음 |
| AC-05c | 삭제 후 새 출력에서 제외하되 이미 내려받은 파일·인쇄물 회수는 보장하지 않음 |

### FR-06 Quest·공동 스탬프 — 승인 범위

기존 경주 9개 Quest를 재사용하고 구성원 누구의 완료든 여행 공동 진행에 반영한다.
필수 ID: daereungwon, cheomseongdae, wolseong, donggung, bulguksa, seokguram, craft, woljeonggyo, museum.
사진 없이 완료 가능하다. 게시글과 Quest 연결은 선택이며 게시글 삭제가 스탬프 취소를 뜻하지 않는 안을 권고한다.

| ID | 검증 시나리오·수용 기준 |
|---|---|
| AC-06a | 두 기기 동시 같은 Quest 완료·재시도 시 공동 스탬프1개, 재접속 후 유지 |
| AC-06b | 종료 후 완료 요청 거부. 서버 저장 실패를 완료 성공으로 표시하지 않음 |
| AC-06c | 1A 화면에 개인 제출·학생 완료자 관리·학교 보고서 동작을 노출하지 않음 |

### FR-07 리더 일기·앨범 출력 — 승인 범위, 세부 편집은 신규 제안

리더가 공동 기록을 선택·정렬하고 기존 A4 템플릿 자산을 활용해 일기·앨범을 저장·인쇄한다.
출력은 선택된 결과물이다. 전체 글·사진 백업, 원본 보존, 복구용 내보내기를 약속하지 않는다.
한 장 수용 개수·긴 글 처리·다중 페이지는 검증 후 결정한다. A4 캔버스 크기가 사진 화질 보장은 아니다.

| ID | 검증 시나리오·수용 기준 |
|---|---|
| AC-07a | 비리더의 출력 구성 변경은 거부하고 리더 선택·순서·템플릿이 미리보기와 결과에 일치 |
| AC-07b | 0개 선택·과다 선택·긴 글·사진 오류 시 빈 출력·잘림·무음 누락 방지와 안내 |
| AC-07c | 출력 직전 확인에서 수정·삭제·접근 상실 감지 시 갱신·재미리보기 제공 |
| AC-07d | 실제 A4 배치·크롭별 사진 품질, PNG 저장·인쇄·CORS를 모바일에서 확인 |

### FR-08 여행 관리·종료 — 승인 범위, 종료 후 게시판 정책은 신규 제안

리더는 참여 현황·공동 진행·초대 링크를 보고 여행을 종료한다. 종료 후 재오픈은 1A에서 제외한다.
종료 시 새 참여·기록 쓰기를 중단하고 기존 구성원 열람·리더 출력을 허용하는 안을 권고한다.
종료 후 삭제 요청·열람 종료·공지 담당자는 외부 파일럿 전 확정한다. 익명 참여자 전원 수신을 보장하지 않는다.
무기한 보관도 90일 자동삭제도 약속하지 않는다. 한정 파일럿은 시작 전에 종료 조건과 처리 담당자를 명시한다.

| ID | 검증 시나리오·수용 기준 |
|---|---|
| AC-08a | 비리더 종료·권한 상승 요청 거부. 종료의 영향을 확인 후 실행 |
| AC-08b | 종료와 게시·참여·Quest 완료 경합 시 종료 후 새 쓰기 확정 차단, 결과 명확히 안내 |
| AC-08c | 종료·보관 종료·영구 삭제를 같은 상태로 표시하지 않음 |

### FR-09 사진 첫 열람 다운로드·캐시 재사용 — 방향 승인, 기술 방식 미결정

첫 열람 때 필요한 사진을 받고 같은 기기의 유효한 사진 캐시를 재사용한다. 전체 사진 선제 다운로드는 제외한다.
