# Our Adventure Phase 1A — 와이어프레임 검토 안내

작성: 2026-10-20 · UX & QA 통합 담당 · 상태: 검토용 모형, 구현 완료 아님

상위 제품 계약은 [PHASE1_PRD.md](PHASE1_PRD.md)를 따른다. 기존 [PHASE1A_UX_SPEC.md](PHASE1A_UX_SPEC.md)의 화면·오류·출력 계약을 모바일 와이어프레임으로 구체화했다. 본 문서의 제안은 미결정 정책을 승인으로 승격하지 않는다.

## 실행과 검토 방식

[와이어프레임 HTML](wireframes/index.html)은 CSS·JavaScript가 내장된 단일 파일이다. 외부 이미지·폰트·라이브러리·API 없이 열린다. 데스크톱에서는 화면 목록, 모바일 폰 프레임, 명세 주석 패널을 함께 보고, 좁은 화면에서는 세로로 배치한다.

화면 목록으로 직접 이동하거나 폰 안의 버튼으로 흐름을 따라갈 수 있다. 리더/구성원 역할과 기본·빈 게시판·저장/사진 실패·종료·정원 초과·출력 사진 누락·출력 선택 없음 상태를 바꿔 검토한다. 모든 샘플 데이터는 JavaScript 메모리에만 있으며 새로고침하면 초기화된다.

## 화면과 요구사항 매핑

| ID | 화면 | FR | 검토할 동작 |
|---|---|---|---|
| S01 | 시작 / 내 여행 | FR-01, FR-10 | 여행 생성·초대 입장·내 여행 진입, 기존 앱 보존 안내 |
| S02 | 여행 만들기 | FR-01 | Google 로그인 성공/취소 모의, 이름 입력, 고정 코스·10명 안내, 생성 실패 |
| S03 | 초대 입장 | FR-02 | 여행 소개·별칭, 실패 시 입력 유지, 종료·정원 도달 차단 |
| S04 | 추억 / 공동 게시판 | FR-03, FR-09 | 기록 목록·사진·자유/Quest 연결, 빈 상태·사진 실패·종료 |
| S05 | 글·사진 작성 | FR-04, FR-05 | 글만/사진만/글+사진, 모의 촬영·선택·제거, 장소 선택, 게시 실패 초안 유지 |
| S06 | 기록 상세 | FR-05, FR-09 | 본인 수정·삭제 모의, 서버 실패 시 기존 데이터 유지, 재열람 캐시 상태 모의 |
| S07 | 리더 선택·순서 | FR-07 | 선택 0개 차단, 버튼으로 정렬, 출력 사진 누락 재시도/제외 |
| S08 | A4 미리보기 | FR-07 | A 앨범/B 스크랩/C 일기 선택, 순서 반영, PNG 저장 모의·브라우저 인쇄 |
| S09 | 여행 관리 | FR-08 | 구성원·초대 링크 모의, 종료 확인·가입/새 기록 차단 |
| S10 | 지도·코스·스탬프 | FR-06 | 기존 9개 Quest 진입, 사진 없이 공동 완료, GPS/길찾기 미제공 |

4탭은 지도 / 코스 / 스탬프 / 추억을 유지한다. 공동 여행의 기본 도착지는 추억 게시판이다. 홈·생성·입장은 여행 참여 전 화면이므로 여행 4탭을 노출하지 않는다. 리더 메뉴인 출력·관리는 구성원 모드에서 비활성화하고 직접 진입도 모형 로직에서 차단한다. 이는 서버 권한 검증 구현을 대체하지 않는다.

## 실제 동작과 모의 동작

| 구분 | 이 파일에서 되는 것 | 실제 구현 여부 |
|---|---|---|
| 화면 | 버튼·탭·목록을 통한 전환, 역할/상태별 렌더 | 검토용 모형 |
| 입력 | 여행 이름·별칭·글·사진 placeholder 선택 | 메모리 안에서만 보존 |
| 게시 | 모의 글 추가·수정·삭제, 실패 후 내용 유지, 처리 중 버튼 비활성화 | 서버 저장·사진 업로드 없음 |
| 사진 | 회색 placeholder, 캐시 적중 문구 모의 | 기기 파일 접근·다운로드·Cache API 없음 |
| 출력 | 선택·순서·템플릿·한 줄 소감, A4 비율 모형, 브라우저 인쇄 | PNG 생성·원본 백업·실제 사진 품질 검증 없음 |
| 초대·인증 | Google 로그인·초대 링크 복사 성공 상태 표시 | 인증·가입 API·클립보드 변경 없음 |
| 기존 데이터 | 보존 안내 | localStorage·기존 앱을 읽거나 변경하지 않음 |

모든 주요 모의 작업은 버튼 또는 배지로 구분한다. 브라우저 인쇄는 회색 사진 모형이 있는 화면을 출력하며, 실제 제품의 Canvas PNG 출력이나 A4 사진 품질을 검증하지 않는다. PNG/일기 한 장은 전체 기록·원본 사진 백업이 아니라는 점을 미리보기 하단에 안내한다.

## 상태별 검토 시나리오

| 상태 | 재현 | 기대 동작 |
|---|---|---|
| 생성/입장 실패 | 실패 선택 후 생성/입장 | 오류·재시도 가능, 이름/별칭 유지 |
| 글 없이 게시 | 작성 화면에서 공백만 입력 | 글/사진 중 하나 필요 안내 |
| 사진 없는 기록 | 글 입력 후 사진 없이 게시 | 정상 게시, 빈 사진 상자 없음 |
| 게시 실패 | 글·사진 모형 선택 후 실패 상태에서 게시 | 성공으로 표시하지 않음, 입력과 사진 모형 유지 |
| 중복 탭 | 게시/생성 처리 대기 중 반복 클릭 | 처리 중 비활성화, 모의 데이터 중복 생성 방지 |
| 사진 조회 실패 | 실패 상태에서 목록/상세 | 본문 유지, 상세 재시도 제공 |
| 정원 초과 | 정원 초과 상태 선택 | 미가입자 입장 차단, 리더 확인·복귀 안내 |
| 종료 | 종료 상태 또는 관리에서 종료 | 새 참여·작성·Quest 완료 차단, 기존 읽기는 정책 제안 모형 |
| 선택 0개 | 출력 선택 없음 상태 | 다음 단계·출력 버튼 비활성화 |
| 출력 사진 누락 | 누락 상태 선택 | 오류 위치 범위 안내, 재시도/기록 제외 전 미리보기 차단 |
| 구성원 역할 | 역할 전환 | 리더 출력·관리 진입 비활성화 |

## 미결정과 의도적 한계

- 글자 수·사진 장수·파일 크기·장변·여행별 저장 한도는 미확정이다. 샘플 사진 1개/기록·출력 기록 2개는 한도가 아니다. UI에 미결정 숫자를 하드코딩한 약속을 하지 않는다.
- 본인 수정·삭제 및 종료 후 읽기·출력은 화면 흐름 검토를 위한 제안이다. 최종 정책 확정과 서버 검증이 필요하다. 리더의 타인 원문 수정 권한은 제공하지 않는다.
- 종료는 즉시 사진 삭제를 뜻하지 않는다. 보관/열람 종료일·내보내기 범위·사전 고지·전원 통지 보장은 아직 결정되지 않았다.
- 첫 열람 후 같은 기기의 유효 캐시 재사용 방향은 승인되었지만, 이 파일은 캐시 기술을 구현하지 않는다. 오프라인 이용·영구 보존·계정 간 복구를 약속하지 않는다.
- 지도는 모형 탐험 진입점이며 GPS나 실제 길찾기가 아니다. 학교 개인 제출·학생 코드·보고서 UI와 30명 지원 약속은 제외한다.
- 실제 게시글/사진 동시 수정·권한 상실·서버 경합·CORS·보안 규칙·10명 원자 가입 제한·기기 저장공간 부족은 이 모형으로 검증할 수 없다.
- Component Gallery의 Tabs·Accordion 패턴을 참고했다. 실제 구현에서 ARIA 탭 키보드 패턴 전체, 포커스 복귀, 화면 읽기 도구 및 실기기 검증이 필요하다.

## 이번 검토에서 확인한 것

2026-10-20 Orchestrator가 Chromium 브라우저의 데스크톱 검토 캔버스에서 확인했다.

| 확인 | 결과 |
|---|---|
| 모의 로그인 → 생성 → 공동 게시판 | 화면 전환 확인 |
| 글만 작성·게시 | 게시판에 새 기록 표시 확인 |
| 게시 실패 | 오류 안내와 입력 내용 유지 확인 |
| 출력 선택·위/아래 정렬 → A4 미리보기 | 변경한 순서 반영 확인 |
| 출력 선택 0개 | 다음 단계 비활성화 확인 |
| 구성원 역할·종료 상태 | 출력/관리 진입 및 새 기록 버튼 비활성화 확인 |
| 검토 데이터 초기화 | 생성 화면에서 바꾼 여행 이름이 기본값으로 복구됨 확인 |
| HTML inline JavaScript | Node 구문 검사 통과, 외부 script 의존 없음 |

이는 모형의 화면·동작 검사다. 실제 Google 인증·서버 권한·사진 업로드·캐시 성능·모바일 실기기·실인쇄는 검증하지 않았다.

## 인계

Product: 정책 수치와 종료/보관/출력 범위를 확정한다. Engineering: 승인된 UX를 데이터·인증·서버 권한·사진 캐시·출력 계약으로 구현한다. QA: 실제 API·두 독립 세션·iOS Safari/Android Chrome·실인쇄 증거를 별도로 기록한다. 이 HTML의 정적·브라우저 검토 통과는 실제 제품의 E2E 통과가 아니다.
