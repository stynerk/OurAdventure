작성: 2026-10-20 · UX & QA 통합 담당 · 상태: 검토용 모형, 구현 완료 아님

상위 제품 계약은 [PHASE1_PRD.md](PHASE1_PRD.md)를 따른다. 기존 [PHASE1A_UX_SPEC.md](PHASE1A_UX_SPEC.md)의 화면·오류·출력 계약을 모바일 와이어프레임으로 구체화했다. 본 문서의 제안은 미결정 정책을 승인으로 승격하지 않는다.

## 실행과 검토 방식

[와이어프레임 HTML](wireframes/index.html)은 CSS·JavaScript가 내장된 단일 파일이다. 외부 이미지·폰트·라이브러리·API 없이 열린다. 데스크톱에서는 화면 목록, 모바일 폰 프레임, 명세 주석 패널을 함께 보고, 좁은 화면에서는 세로로 배치한다.

화면 목록으로 직접 이동하거나 폰 안의 버튼으로 흐름을 따라갈 수 있다. 리더/구성원 역할과 기본·빈 게시판·저장/사진 실패·종료·정원 초과·출력 사진 누락·출력 선택 없음 상태를 바꿔 검토한다. 모든 샘플 데이터는 JavaScript 메모리에만 있으며 새로고침하면 초기화된다.

4탭은 지도 / 코스 / 스탬프 / 추억을 유지한다. 공동 여행의 기본 도착지는 추억 게시판이다. 홈·생성·입장은 여행 참여 전 화면이므로 여행 4탭을 노출하지 않는다. 2026-10-21 사용자 승인에 따라 여행 상단의 ‘여행 관리’와 추억 탭의 ‘앨범 만들기’는 리더에게만 표시하고 구성원 화면에서는 숨긴다. 하단 4탭은 두 역할 모두 동일하다. 직접 진입은 모형 로직에서도 차단한다. 외부 검토 도구의 화면 목록은 제품 UI와 구분한다. 이는 서버 권한 검증 구현을 대체하지 않는다.

## 실제 동작과 모의 동작

| 구분 | 이 파일에서 되는 것 | 실제 구현 여부 |
|---|---|---|
| 화면 | 버튼·탭·목록을 통한 전환, 역할/상태별 렌더 | 검토용 모형 |
| 입력 | 여행 이름·별칭·글·사진 placeholder 선택 | 메모리 안에서만 보존 |
| 게시 | 모의 글 추가·수정·삭제, 실패 후 내용 유지, 처리 중 버튼 비활성화 | 서버 저장·사진 업로드 없음 |
| 사진 | 회색 placeholder, 캐시 적중 문구 모의 | 기기 파일 접근·다운로드·Cache API 없음 |
| 출력 | 선택·순서·템플릿·한 줄 소감, A4 비율 모형, 브라우저 인쇄 | PNG 생성·원본 백업·실제 사진 품질 검증 없음 |
| 초대·인증 | Google 로그인·초대 링크 복사 성공 상태 표시 | 인증·가입 API·클립보드 변경 없음 |
| 기존 데이터 | 보존 안내 | localStorage·기존 앱을 읽거나 변경하지 않음 |

모든 주요 모의 작업은 버튼 또는 배지로 구분한다. 브라우저 인쇄는 회색 사진 모형이 있는 화면을 출력하며, 실제 제품의 Canvas PNG 출력이나 A4 사진 품질을 검증하지 않는다. PNG/일기 한 장은 전체 기록·원본 사진 백업이 아니라는 점을 미리보기 하단에 안내한다.

## 미결정과 의도적 한계

- 글자 수·사진 장수·파일 크기·장변·여행별 저장 한도는 미확정이다. 샘플 사진 1개/기록·출력 기록 2개는 한도가 아니다. UI에 미결정 숫자를 하드코딩한 약속을 하지 않는다.
- 진행 중 본인 수정·삭제와 리더의 타인 원문 변경 금지는 2026-10-21 사용자 승인 범위다. 종료 후 읽기·출력 및 삭제 처리는 별도 정책 확정이 필요하다. 서버 권한 검증은 미완료다.
- 종료는 즉시 사진 삭제를 뜻하지 않는다. 보관/열람 종료일·내보내기 범위·사전 고지·전원 통지 보장은 아직 결정되지 않았다.
- 첫 열람 후 같은 기기의 유효 캐시 재사용 방향은 승인되었지만, 이 파일은 캐시 기술을 구현하지 않는다. 오프라인 이용·영구 보존·계정 간 복구를 약속하지 않는다.
- 지도는 모형 탐험 진입점이며 GPS나 실제 길찾기가 아니다. 학교 개인 제출·학생 코드·보고서 UI와 30명 지원 약속은 제외한다.
- 실제 게시글/사진 동시 수정·권한 상실·서버 경합·CORS·보안 규칙·10명 원자 가입 제한·기기 저장공간 부족은 이 모형으로 검증할 수 없다.
- Component Gallery의 Tabs·Accordion 패턴을 참고했다. 실제 구현에서 ARIA 탭 키보드 패턴 전체, 포커스 복귀, 화면 읽기 도구 및 실기기 검증이 필요하다.

## 인계

Product: 정책 수치와 종료/보관/출력 범위를 확정한다. Engineering: 승인된 UX를 데이터·인증·서버 권한·사진 캐시·출력 계약으로 구현한다. QA: 실제 API·두 독립 세션·iOS Safari/Android Chrome·실인쇄 증거를 별도로 기록한다. 이 HTML의 정적·브라우저 검토 통과는 실제 제품의 E2E 통과가 아니다.

## 2026-10-21 변경

공통 하단 4탭 유지. 리더 전용 ‘여행 관리’를 여행 화면 상단에 배치하고 추억 탭의 출력 진입을 ‘앨범 만들기’로 표기한다. 참여자에게 두 진입점을 숨긴다. 모형의 기존 직접 진입 차단을 유지한다. 실제 인증·API 권한·기기 검증을 통과했다는 뜻은 아니다.

## 11. 참여자 계정 연결 UX 검토 — 2026-10-21

상태: UX 독립 전문가 검토 완료. 사용자는 검토 진행을 요청했으며, 세부 UX는 아래 권고안이다. 실사용 테스트·계정 연결 구현·운영 검증 완료를 뜻하지 않는다.

| 접점 | 권고 동작 |
|---|---|
| 초대 입장 | 별칭 참여 유지. 기기 변경·브라우저 데이터 삭제 시 기존 작성자 접근이 어려울 수 있음을 안내. 강제 가입 팝업 없음 |
| 첫 기록 저장 성공 | 서버 확정 후 닫을 수 있는 비차단 계정 연결 카드 1회. Google 계정 연결 / 나중에 제공. 저장 실패·작성 도중에는 자동 노출하지 않음 |
| 상시 진입 | 공통 상단 프로필·별칭 메뉴 및 ‘내가 쓴 기록’의 작은 CTA. 리더 전용 여행 관리와 구분. 하단 4탭 유지 |
| 재노출 | 여행·참여자별 안내 1회; 닫은 뒤 자동 반복 없음. 연결 완료 시 CTA 제거 |
| 공유 범위 | ‘내 기록’ 대신 ‘내가 쓴 기록’ 권고. 작성 시 ‘이 여행 구성원 모두에게 공유되며, 리더가 앨범에 포함할 수 있어요.’ 표시 |
| 공동 스탬프 | 제목 ‘우리가 함께 모은 스탬프’. 최초 완료 별칭·시각 표시 권고. 개인 수행 이력과 구분 |

연결 안내 초안: ‘다른 기기에서도 내가 쓴 기록을 이어서 관리하려면 계정을 연결하세요.’ 이 효용 문구는 교차기기 조회·권한 유지 검증 후 사용한다. 계정 연결은 영구 보관·백업이나 리더 승격을 뜻하지 않는다.

필수 출시 조건: 연결 후 기존 기록 소유권·멤버십·정원·역할 유지. 취소·실패 시 기존 참여 상태 유지. 이미 사용 중인 Google 계정과의 충돌은 자동 병합하지 않으며 별도 처리 규칙이 필요하다. 이미 잃어버린 익명 세션을 동일 별칭으로 복구하지 않는다.

첫 검증: 가입 거절 후 이용 / 첫 게시 성공 시점 노출 / 성공 후 소유권·정원·역할 유지 / 취소·계정 충돌 시 원상태 유지 / 공유 범위·공동 완료 의미 이해. 실제 검증 미실행.

Engineering/QA 독립 설계 검토 결과도 같은 조건을 지지했다. Firebase 공식 계정 연결 문서: https://firebase.google.com/docs/auth/web/account-linking . 동일 UID 연결이 기본이며, 이미 사용 중인 계정 충돌 병합은 별도 앱 책임이다. 현재 프로젝트에서 SDK 동작 확인이 필요하다.

출시 게이트: UID·소유권·멤버십·정원·역할 유지, 취소/실패 후 기존 세션 유지, 동일 별칭 분리 검증 전 실제 연결 CTA를 활성화하지 않는다. 기존 계정 충돌 처리 및 다른 기기 재접속 검증 전 교차기기 효용을 약속하지 않는다. UX·Engineering/QA 검토는 실제 별도 서브에이전트가 수행했으며, 기존 역할별 대화 스레드의 실행 결과로 간주하지 않는다.
