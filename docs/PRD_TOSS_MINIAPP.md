원칙: **기능 정의는 PRD v2에 한 번만** 쓴다. 이 문서는 "무엇을 빼고, 무엇이 토스에서 다르게 동작하는지"만 쓴다. 미니앱에서 검증된 변경은 PRD v2로 올린다.

## 1. 한 줄 정의

**토스 안에서 링크 하나로 들어와, 그룹이 함께 여행 코스를 짜고 장소마다 사진 도장을 모으는 미니앱.**

## 2. 왜 토스 미니앱으로 먼저 하나

- 설치 없이 링크로 바로 참여 → 멤버 참여 장벽(목표 45초)을 가장 낮춘다.
- 친구·가족 단체방에 공유 링크로 퍼지는 구조가 우리 초대 흐름과 맞다.
- 기존 웹 앱을 WebView로 올릴 수 있어 새로 만드는 양이 적다.

검증하고 싶은 가설:
1. 리더가 **1분 안에** 자동 코스를 만들고 초대 링크를 보낸다.
2. 초대받은 멤버 절반 이상이 링크로 들어와 **도장 1개 이상**을 받는다.
3. 여행 후 리포트·이미지를 1회 이상 저장·공유한다.

## 3. 범위

### 포함 (프로토타입)

| PRD v2 | 미니앱에서 |
|---|---|

| F2 여행·코스·스탬프 | 목적지·날짜 + 장소 직접 검색(현재 구현). **코스 추천(자동 일정·일차 일정표·함께 고르기)은 [v2](PRD_TOSS_MINIAPP_V2.md)** |
| F3 초대·참여 | 토스 공유하기 + 자동 초대 문구(T19). 멤버는 별칭만 입력 |
| F4 사진 도장 | 그대로. 카메라·앨범 권한은 토스 WebView 동작 확인 필요 |

### 제외 (일반 서비스에서 다룸)

여러 여행을 묶는 그룹 관리 화면 · 경주 예시 코스 · 멤버 PICK 투표(T20) · 숙소·경비 · 다국어(EN) · 결제·인앱 광고.

## 4. 로그인 (가장 큰 결정)

공식 안내상 **미니앱 출시는 사업자 등록 없이 가능하지만, 토스 로그인은 사업자 등록이 필요**하다.

| 안 | 내용 | 장점 | 위험 |
|---|---|---|---|
| A. 토스 로그인 | 토스 인증 → 서버(Functions)에서 Firebase 커스텀 토큰 발급 | 한 번 탭으로 로그인, 가장 자연스러움 | 사업자 등록 필요, 서버 작업 추가 |
| B. 익명 + 초대 링크 | Firebase 익명 로그인. 리더도 익명으로 시작하고, 일반 서비스 전환 시 계정 연결 | 사업자 없이 바로 가능, 참여 가장 빠름 | 기기를 바꾸면 기록 복구 불가(안내 필요), 리더 권한 보호 약함 |
| C. Google 로그인 | 지금 웹 방식 그대로 | 코드 재사용 | WebView에서 Google 로그인 창이 막힐 가능성 높음 → 비추천 |

**확정 (2026-10-30 사용자): A안 토스 로그인** (사업자 등록 있음). **초대받은 멤버도 토스 로그인 후 참여**한다(로그인 없는 참여는 하지 않음). 사용자 식별자는 Firebase UID로 통일해 일반 서비스와 데이터 구조를 공유한다.

- 흐름: 초대 링크 → 그룹·여행 미리보기(이름·기간·장소 수만) → **토스로 계속하기** → 별칭 입력 → 참여.
- 토스 로그인으로 받는 개인정보는 최소 범위만 요청한다. 이름·전화번호는 저장·표시하지 않고, 화면에는 별칭만 쓴다.
- 참여 목표 45초는 유지하고, 로그인 단계 이탈률을 따로 측정한다(`login_start`·`login_success`에 `channel: toss`).

## 5. 토스에서 달라지는 것

| 항목 | 규칙 |
|---|---|
| 진입 | 미니앱 첫 화면 = "어디로·언제" (코스 구성 개선안 ①). 로그인 화면 없이 바로 시작, 필요할 때 로그인 |
| 상단 | 토스가 그리는 상단 바(앱 이름·⋯·닫기)를 쓴다. 우리 화면에 자체 뒤로 가기 바를 중복으로 두지 않는다 |
| 공유 | 토스 공유 기능으로 초대 링크를 보낸다. 링크를 열면 미니앱의 해당 여행 참여 화면으로 바로 들어온다 |
| 사진 | 사진 찍기·앨범 선택이 토스 WebView에서 동작하는지 스파이크에서 확인. 안 되면 SDK 기능으로 대체 |
| 디자인 | [디자인 가이드 v2](DESIGN_SYSTEM.md) 유지. 토스 디자인 가이드와 충돌하는 부분(상단 바, 주 버튼 위치, 시스템 글꼴)은 토스를 따른다 |
| 약관 | 개인정보 처리방침·이용약관 링크 필수. 수집 항목은 별칭·사진·한 줄 기록뿐임을 명시 |
| 분석 | GA4 이벤트는 [데이터 트래킹 명세](ANALYTICS_SPEC.md) 그대로, 공통 파라미터에 `channel: toss` 추가 |

## 6. 구조 (일반 서비스 확장 대비)

- **백엔드 공유**: 같은 Firebase 프로젝트(our-adventures-5ce50)의 Firestore·Storage·Functions를 쓴다. 데이터 모델은 PRD v2 6절 그대로.
- **화면 공유**: 웹 앱 코드를 그대로 쓰고, 토스 전용 차이(로그인·공유·상단 여백·권한)는 **채널 어댑터** 한 곳에 모은다. `if (channel === 'toss')`를 화면 곳곳에 흩뿌리지 않는다.
- **빌드**: 같은 저장소에서 `web` / `toss` 두 출력. 토스 쪽은 앱인토스 WebView SDK로 감싼다. iframe으로 감싸지 않는다(반려 사유).
- 일반 서비스로 확장할 때는 어댑터를 `web`으로 바꾸고, 미니앱에서 뺀 기능(3절 제외)을 PRD v2 기준으로 더한다.

## 7. 검수·출시 체크

- iframe 사용 없음 · 토스 상단 바와 겹침 없음 · 개인정보 처리방침·약관 링크 · 누를 수 있는 요소 44px 이상 · 오류·빈 화면 문구 · 로그인 없이도 첫 화면 동작 · 사진 업로드 실패 시 재시도 안내.
- 앱 이름·아이콘·소개 문구·미리보기 이미지 4장(Codex 제작).
- 검수 기준은 자주 바뀌므로 제출 전 앱인토스 개발자 센터 최신 문서로 다시 확인한다.
